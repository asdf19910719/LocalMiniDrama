## 1. 文档目的

本文把 LocalMiniDrama 当前可运行产品还原为一份完整的 As-Is PRD，用于：

- 防止下一大版本只根据竞品外观改造，误删已有深层能力；
- 为 RunningHub 对标建立同一粒度的功能清单；
- 明确现有页面、接口、数据和后台服务中哪些可以复用，哪些是兼容负债；
- 为 V2.1 的迁移、验收和回归测试提供事实基线。

本文不把设计设想写成已实现能力。每个结论使用 A/B/C/D/U 证据等级，定义见本目录 [README](./README.md)。

## 2. 产品摘要

### 2.1 当前定位

LocalMiniDrama 是一个本地优先、面向 AI 短剧单集制作的桌面 Web 工作台。它以项目和剧集为组织单位，把剧本、角色/场景/道具、分镜、图片、视频、音频和合片能力放在同一套本地服务中，并允许接入多个外部 AI Provider。【A/B】

当前产品的核心优势不是“页面流程成熟”，而是已经积累了较深的生产基础设施：H3 提示词编译、引用槽位、Director 候选与锚点、任务恢复、外部网页生成、剧集包导入导出、音频规划、视频合并和超分。【B/C】

当前产品的核心问题是，这些能力主要聚合在一个超长制作页及若干技术型入口中，缺少清晰的阶段状态、批准语义、影响范围、候选决策和交付收口。【A/B】

### 2.2 目标用户

当前实现最适合以下用户：【A/B/D】

1. 在本机管理素材和生成任务的个人创作者；
2. 熟悉模型、提示词、引用图和生成参数的进阶用户；
3. 需要人工逐镜干预、保留多个候选并组合成片的导演/剪辑型用户；
4. 需要在 API 生成与外部网页生成之间切换的用户。

当前产品没有形成团队席位、云审阅、评论指派或公开发布工作流，不应把多人制片团队写成已服务用户。【A/B】

### 2.3 核心价值

- 项目资产、数据库和生成产物本地保存，用户对文件拥有直接控制权。【B】
- 从剧本到资产、分镜、图片、视频、音频、合片具备较完整的技术链路。【B/C】
- 支持多 Provider 和 Provider 能力差异，而非绑定单一模型。【B】
- H3、Director、引用槽位和 provenance 能保存比普通“提示词输入框”更丰富的镜头上下文。【B/C】
- 支持人工生成、批量生成、外部网页回填和失败恢复等多种生产方式。【A/B/C】

## 4. 系统与运行架构

### 4.1 服务组成

```text
Vue 3 + Vite 前端（3013）
        │ /api、/static 代理
        ▼
Express 后端（5679）
        ├─ SQLite 本地数据库
        ├─ 本地静态媒体与缓存
        ├─ Provider/API 适配
        ├─ 外部网页生成任务
        ├─ Director/H3/引用编译
        └─ 音频、合片、超分与任务恢复
```

前端构建产物存在时，也可由后端在 5679 端口托管。【B】

### 4.2 顶层路由与信息架构

| 路由 | 页面 | 当前职责 | 证据 |
|---|---|---|---|
| `/` | 项目列表 `FilmList` | 项目入口、公共资产入口、导入/新建、主题与配置 | A/B |
| `/drama/:id` | 项目详情 `DramaDetail` | 项目信息、风格/画幅/默认模型、剧集和资产入口 | A/B |
| `/film/:id` | 制作页 `FilmCreate` | 单集几乎全部生产功能 | A/B |
| `/film/:id/canvas` | 剧集画布 `DramaCanvas` | 以剧集为上下文的高级画布 | A/B |
| `/drama/:id/canvas` | 项目画布 `DramaCanvas` | 以项目为上下文的画布入口 | B |
| `/ai-config` | AI 配置 `AiConfig` | Provider、模型、业务场景和提示词配置 | A/B |
| `/free-create` | 自由创作 `FreeCreate` | 快速图片/视频生成 | A/B |
| `/media-library` | 媒体库 `MediaLibrary` | 图片和视频聚合浏览 | A/B |

当前信息架构以“页面功能集合”组织，而不是以“单集生产阶段”组织。自由创作入口在项目列表源码中被隐藏/注释，媒体库和配置则以全局入口存在。【A/B】

### 4.3 页面复杂度基线

| 页面组件 | 约行数 | 判断 |
|---|---:|---|
| `FilmCreate.vue` | 11,496 | 单文件承载过多业务、状态和视图，是主要拆分对象 |
| `DramaDetail.vue` | 1,750 | 项目设置、剧集和资产入口耦合 |
| `FilmList.vue` | 1,350 | 项目管理和全局导航入口 |
| `DramaCanvas.vue` | 1,284 | 高级视图，当前引导与可读性不足 |
| `FreeCreate.vue` | 587 | 独立生成入口，功能相对轻 |
| `MediaLibrary.vue` | 480 | 聚合浏览基础版 |

行数只用于识别维护风险，不等于功能价值或代码质量结论。【B】

## 5. 核心业务对象

### 5.1 对象层级

```text
项目 Drama/Project
  ├─ 项目设置：名称、视觉风格、画幅、默认模型
  ├─ 剧集 Episode
  │   ├─ 剧本/解析结果
  │   ├─ 角色 Character
  │   │   └─ 阶段图、身份锚点、提示词、库来源
  │   ├─ 场景 Scene
  │   │   └─ 图片、提示词、库来源
  │   ├─ 道具 Prop
  │   │   └─ 图片、负向提示词、库来源
  │   ├─ 分镜 Storyboard
  │   │   ├─ 镜头字段、叙事/台词、人物与资产关联
  │   │   ├─ 图片生成与候选
  │   │   ├─ H3 提示词草稿/编译来源
  │   │   ├─ 引用槽位/锚点
  │   │   ├─ 视频候选、参考音频、AV 契约
  │   │   └─ Director artifact/候选/质量结果
  │   ├─ 音频计划与 TTS/混音
  │   ├─ 合片与超分任务
  │   └─ 剧集包与导入 provenance
  └─ 项目资产库/公共资产库
```

### 5.2 生成与任务对象

- 图片生成记录及异步任务状态；
- 视频生成记录、开始/完成时间、参考音频和 Provider 参数；
- H3 草稿、workflow id 和 skill provenance；
- 外部网页生成会话、任务、加固状态和回填结果；
- Director 候选、artifact、锚点、时间线和质量记录；
- 视频超分任务及恢复状态；
- 剧集包导入记录和来源追踪。

这些对象已在迁移 `01` 至 `35`、API 模块和服务层中出现。【B/C】

### 5.3 当前语义缺口

现有数据能表达“有一张图/一个候选/一个任务”，但没有贯穿全链路、用户可见且一致的以下语义：【B/D】

- 当前批准版本；
- 上游变更后谁被影响、为何 stale；
- 阶段是否可以完成、被什么阻塞；
- 一镜的完整输入快照 Shot Package；
- 一个候选从哪份剧本、Look、资产和 prompt 编译而来；
- 哪个时间线版本已经 Picture Lock；
- 哪个导出包是最终交付版。

这些缺口是 V2.1 新领域模型的主要理由，而不是简单换皮。

## 6. 当前端到端主流程

### 6.1 新建或导入项目

1. 用户进入项目列表；
2. 可新建项目或导入已有项目包；
3. 新建时填写项目基础信息；
4. 项目卡片提供进入、编辑、导出和删除；
5. 进入项目详情后继续设置风格、画幅和默认模型。【A/B】

问题：项目卡片对最近进度、阻塞任务、下一步和最后编辑镜头提示不足；页面大片留白，项目级生产状态不突出。【A】

### 6.2 创建与管理剧集

1. 在项目详情查看剧集列表；
2. 新建单集或批量导入；
3. 选择单集进入制作页；
4. 可通过 JSON、剧集包或外部 AI 相关入口交换数据；
5. 项目级角色/场景/道具与剧集生产资产在同页附近呈现。【A/B】

问题：项目配置、项目圣经、剧集列表和导入工具缺少层级分区；“进入制作”的阶段状态不可见。【A】

### 6.3 单集制作：手工路径

当前制作页以纵向长页面组织，典型路径为：【A/B】

1. 输入或编辑剧本；
2. 解析/生成角色、场景、道具和分镜；
3. 为角色、场景、道具编辑提示词、上传或生成图片；
4. 在分镜卡中调整景别、机位、画面描述、台词/旁白、资产引用；
5. 为每镜生成或选择图片；
6. 生成/编辑 H3 视频提示词和参考关系；
7. 为每镜生成视频候选、检查并选择；
8. 配置音频、旁白或参考音频；
9. 配置合片并产出视频；
10. 必要时执行超分或外部工具流程。

页面支持很深的逐项控制，但用户需要通过滚动、折叠区和横向区域自行维护上下游关系。当前样例全页截图高度超过 10,000 像素，是认知负担的直接证据。【A】

### 6.4 单集制作：一键/批量路径

制作页提供一键或批量生成入口，并显示剧集级生成进度。【A/B】

典型行为包括：

- 批量生成资产图片；
- 批量生成分镜图片；
- 批量生成视频；
- 轮询或恢复异步任务；
- 在失败后对具体任务重试；
- 根据可用 Provider 切换生成路径。

问题：批量动作与“输入是否已经确认”没有统一批准门禁；进度更像任务统计，不是阶段就绪度；用户难以预估影响范围和远端费用。【A/B/D】

### 6.5 外部网页生成路径

系统能为无法或不适合直接 API 调用的 Provider 建立外部网页生成任务，并保存会话、参数、来源和回填结果。【B/C】

产品价值：

- 保留统一项目上下文；
- 让外部生成结果回到镜头/资产；
- 记录 provenance，而非完全脱离项目手工下载上传。

当前问题：外部任务、API 任务和本地任务的统一状态、费用提示、取消/重试策略和全局任务中心仍不够产品化。【A/B】

### 6.6 高级画布路径

用户可从项目或剧集进入画布，以图或列表/时间线方式查看生产对象和关系，并执行部分批量图片/视频工作流。【A/B】

当前画布适合作为高级用户的关系视图，但不适合作为默认主流程：

- 初始图缩放较小，可读性弱；
- 节点与“下一步该做什么”没有强引导；
- 与制作页的编辑职责有重叠；
- 阶段 Gate、版本和失效关系没有成为画布一等视觉语言。

V2.1 应保留画布，但所有写操作必须走统一领域 API，不能形成旁路。

### 6.7 自由创作路径

自由创作提供图片和视频两类快速生成表单，适合测试模型或制作临时素材。【A/B】

当前限制：

- 入口发现性弱；
- 生成结果如何归入项目、剧集、角色、场景、道具或镜头不够明确；
- 缺少 Recipe、来源、用途和后续入库引导；
- 与生产工作台中的生成表单存在体验分叉。

### 6.8 媒体库路径

媒体库聚合展示图片和视频，并提供类型筛选。【A/B】

当前限制：

- 多个资产只显示 `original.png` 等通用文件名；
- 缺少项目/剧集/镜头、角色/场景/道具、Provider、日期、状态、标签等筛选；
- 缺少来源、使用位置、批准状态和版本关系；
- 缺少“设为镜头候选/角色版本/场景参考”等语义化操作。

### 6.9 AI 配置路径

AI 配置集中承载 Provider、模型、协议、业务场景、提示词、生成参数和 Stable Diffusion 相关配置。【A/B】

当前价值是灵活、可本地接入多种服务；当前问题是配置密度高、技术字段直接暴露、Provider 能力与具体生成表单可能不完全同源，普通用户难以判断哪些配置是全局默认、业务覆盖或单次覆盖。【A/B】

## 7. 页面级功能清单

### 7.1 项目列表

已实现：【A/B】

- 项目卡片浏览和进入；
- 新建项目、导入项目；
- 编辑、导出、删除项目；
- 角色库、场景库、道具库入口；
- AI 配置、主题切换、联系入口；
- 项目封面/摘要展示。

体验问题：【A】

- 项目状态、最近剧集、任务异常和下一步不突出；
- 卡片和首屏空间利用率低；
- 全局工具与制作入口的层级不够清晰；
- 自由创作存在能力但主导航发现性不足。

### 7.2 项目详情

已实现：【A/B】

- 项目标题和基础设置；
- 视觉风格、画幅、默认图片 Provider/模型；
- 剧集列表、新建与批量导入；
- 外部 AI、JSON/包相关入口；
- 角色、场景、道具及生产资产入口；
- 进入制作或画布。

体验问题：【A】

- 设置、项目圣经、剧集管理和数据工具混排；
- 看不到每集四阶段进度和阻塞原因；
- “选择风格/模型”与“批准用于本集”语义未区分。

### 7.3 制作页顶部与剧本区

已实现：【A/B】

- 返回项目、显示剧集身份；
- 剧本编辑/处理入口；
- 一键生成与进度；
- 画布、外部 AI、包/JSON 等辅助入口；
- 音频计划或全局生成设置。

体验问题：【A】

- 顶部动作数量多，主次不清；
- 上游编辑与下游批量执行在同一页面，没有阶段 Gate；
- 长任务离开当前滚动位置后不易追踪。

### 7.4 角色、场景、道具区

已实现：【A/B/C】

- 角色、场景、道具列表和编辑；
- 提示词/负向提示词；
- 上传、生成、重生成、选择图片；
- 角色身份锚点、角色阶段与本地路径；
- 从公共库引用或写回库；
- 多 Provider/模型相关生成参数。

体验问题：【A/B】

- 卡片横向空间过宽并出现横向滚动；
- 卡内动作密集，编辑、生成、版本、状态混在一起；
- 当前选择、批准版本和历史候选不够明确；
- 上游变化会影响哪些分镜缺少可见解释。

### 7.5 分镜图片区

已实现：【A/B/C】

- 分镜顺序和镜头结构字段；
- 画面描述、对白/旁白、景别、机位等；
- 角色、场景、道具关联；
- 图片提示词和覆盖；
- 图片生成、上传、候选与当前图；
- 镜头分段、通用模式、叙事字段；
- 任务状态、失败重试和批量处理。

体验问题：【A/B】

- 单卡同时承担脚本、导演、引用、生成和选择，层次密；
- 候选比较、采用理由和历史版本不够集中；
- 镜头之间连续性和上/下一镜引用缺少专门视图；
- 批量操作的范围、跳过规则和费用预估不够透明。

### 7.6 H3、引用和视频区

已实现：【A/B/C】

- H3 提示词草稿、编译与 provenance；
- Director R2V 等默认或工作流映射；
- 角色身份、首尾帧、参考图/音频等引用能力；
- canonical 引用槽位与 Provider 映射基础；
- 视频生成、候选、开始/完成状态；
- 外部网页生成与回填；
- 视频质量/Director artifact 基础；
- 视频超分任务。

体验问题：【A/B】

- 技术概念过多暴露在主卡片；
- Provider 不支持某引用时的降级解释不统一；
- H3/Look/资产变化后的 stale 关系需要更明确；
- 当前视频、候选、超分版本与最终时间线版本关系不够可视。

### 7.7 音频、合片与输出区

已实现：【A/B/C】

- 分镜旁白/对白承载；
- 音频计划、参考音频和视频生成关联；
- TTS/混音服务基础；
- 视频合并与参数；
- 超分和剧集包/结果输出。

体验问题：【A/B】

- 后期不是独立的“剪辑与交付”阶段；
- 时间线版本、Picture Lock、字幕、响度、调色和交付检查缺少统一 Gate；
- 技术处理顺序及失败回退没有形成用户可理解的流水线。

## 9. 状态、错误与恢复现状

### 9.1 已有状态能力

系统在技术层已能记录多类任务的排队、运行、完成、失败和时间字段，也存在按剧集汇总进度的 API。【B/C】

### 9.2 产品层缺口

当前缺少一套跨对象、跨页面一致的状态语言：【A/B】

| 需要的状态语义 | 当前表现 | V2.1 方向 |
|---|---|---|
| 草稿/已批准 | 编辑值与当前值混合 | 显式 approval revision |
| 可开始/被阻塞 | 依赖散落在表单和错误消息 | stage blocker list |
| 新鲜/过期 | 某些 H3/任务有来源，但 UI 不统一 | fingerprint + stale reason |
| 当前/候选/历史 | 分散在各对象卡片 | 统一 candidate rail 与 history |
| 运行/可取消/可重试 | 各任务类型表现不同 | 全局 task drawer 和统一动作 |
| 已锁定/可编辑 | 合片配置存在但交付语义弱 | Picture Lock + Delivery Gate |

### 9.3 失败恢复原则

当前产品已经具备可恢复任务的技术基础，V2.1 不应重写为“失败即丢失”。目标是把已有恢复能力统一展示为：失败原因、受影响对象、已完成数量、是否扣费未知/已知、重试范围、回退产物和日志入口。【B/D】

## 10. 本地优先与 Provider 策略

### 10.1 当前本地优先事实

- SQLite、本地静态目录和本地缓存是核心持久化；
- 用户可直接导入导出项目和媒体；
- Provider 凭据和模型通过本地配置接入；
- 产品不依赖平台账户、团队或云项目才能浏览和编辑本地内容。【B】

### 10.2 当前 Provider 策略

系统支持不同 API 协议、模型映射、图片/视频能力、外部网页路径和特定工作流。Provider 的引用图数量、首尾帧、参考音频、分辨率或时长等能力并不天然一致。【B/C】

V2.1 必须保持：

1. Provider 能力由后端契约/适配器提供，前端不硬编码长期规则；
2. 本地编辑、预览和本地工具默认可直接执行；
3. 任何可能触发远端计费的生成，执行前展示 Provider、模型、范围和预计数量；
4. 不支持的引用必须阻止或明确降级，不能静默丢弃；
5. 生成结果连同输入快照和 Provider 响应摘要保存。

## 11. 数据保护、兼容和非功能基线

### 11.1 数据保护

- 删除项目是不可逆高风险动作，应继续二次确认；
- 导入不得静默覆盖同名项目或现有资产；
- 凭据不得出现在截图、日志或导出包；
- 外部生成回填必须验证文件类型、来源和对象归属；
- 数据库迁移需自动执行且保持旧项目可打开。

### 11.2 性能

当前超长页面会加载和观察大量对象，项目规模增大后存在全量渲染、深度 watch、媒体加载和多点轮询风险。【A/B】

V2.1 的现状回归基线：

- 200 镜项目不能一次加载全部视频二进制；
- 媒体缩略图懒加载；
- 镜头轨虚拟化；
- 单镜保存不触发整集深度更新；
- 任务轮询按剧集/任务流聚合；
- 候选和历史分页。

### 11.3 可用性与可访问性

当前浅色/深色模式可切换，但不同页面的强调色、信息密度和横向滚动不一致；键盘操作、焦点状态、错误摘要和窄屏策略尚未形成统一规范。【A】

### 11.4 运行兼容

后端原生依赖与 SQLite ABI 以 Node.js 22.22.3 为验证基线。后续实现和 CI 应固定该版本，避免开发机默认 Node 24 导致 `better-sqlite3` 兼容问题。【B/C】

## 12. 当前优势：必须保留

| 能力 | 为什么不能因对标而丢失 |
|---|---|
| 本地优先数据与文件控制 | 是与纯云平台的根本差异和用户信任基础 |
| H3 结构化提示词与 provenance | 支撑可复现、可比较、可追踪的镜头生成 |
| canonical references/slots | 能隔离业务引用意图与 Provider 参数差异 |
| Director candidates/artifacts/anchors | 已具备候选决策与连续性治理的深层数据基础 |
| 外部网页生成回填 | 覆盖无稳定 API 的生产现实 |
| 任务恢复 | 长耗时生成不可缺少，避免失败后重做 |
| 剧集包和导入 provenance | 支撑迁移、备份、复盘和交付 |
| 音频、合片、超分 | 使产品不止停留在“生成若干镜头素材” |

## 13. 当前主要问题：必须改造

### P0：生产正确性

1. “选择”与“批准”语义不分；
2. 上游剧本、Look、资产变更后的失效范围不可见且不统一；
3. 不同 Provider 的引用能力缺少同源门禁；
4. 候选、当前产物、后处理版本和最终时间线关系不清；
5. 阶段完成条件和阻塞项不明确。

### P1：主流程与认知负担

1. 11,000 行级制作页形成超长单页；
2. 用户无法快速判断“现在在哪、下一步是什么、还缺什么”；
3. 批量生成与远端成本提示不充分；
4. 任务状态分散；
5. 高级技术字段挤占普通用户路径。

### P2：资产与交付治理

1. 媒体库缺少语义标签、来源、使用位置和版本；
2. 自由创作结果回归项目的路径弱；
3. 时间线、Picture Lock、后期和 Delivery Gate 不完整；
4. 项目首页缺少全局生产摘要和异常视图；
5. 响应式、键盘与可访问性规范不足。

## 14. As-Is 验收基线

下一版本迁移不能以“新页面能打开”为完成，至少要保持以下能力可用：

1. 现有项目和剧集能无损打开；
2. 角色、场景、道具、分镜、图片和视频关联不丢失；
3. 现有图片/视频文件仍可预览；
4. Provider 和业务场景配置继续生效；
5. 手工单镜和批量生成路径可用；
6. H3 草稿、引用、候选和 provenance 可读取；
7. 外部网页生成任务与回填不被切断；
8. 音频、合片和超分能力可从新流程到达；
9. 项目/剧集包导入导出保持兼容；
10. 失败任务可以识别和恢复；
11. 旧 `/film/:id` 路径在迁移期提供只读或明确跳转；
12. 不要求用户注册云账户才能继续本地创作。

## 15. 现状结论

LocalMiniDrama 当前不是“缺少功能的原型”，而是“能力深但产品编排不足的本地生产工具”。因此大版本升级的正确方向不是复刻 RunningHub 页面，而是用四阶段工作台、批准与失效、Shot Package、候选/历史、时间线锁定和交付 Gate，把现有技术能力组织成可理解、可追踪、可恢复的生产系统。

对应的逐项竞品差异和处理决策见 [RunningHub × LocalMiniDrama 全量差异矩阵](./runninghub-localminidrama-gap-matrix.md)。
