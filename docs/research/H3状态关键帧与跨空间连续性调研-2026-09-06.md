# H3 状态关键帧与跨空间连续性调研

日期：2026-09-06

## 问题

上一镜中男主在酒店房内、女主在走廊，下一镜要求女主跨过门槛进入房间。仅使用上一镜截图作为普通 Ref2VA 参考时，H3 容易保持门口构图却不完成跨门，甚至让女主沿走廊离开。本调研检查这是否为行业常见问题、提示词是否合规，以及可复用的解决路径。

## 官方资料结论

1. MiniMax 官方将 H3 Ref2VA 定义为多模态参考生成，可使用最多 9 张图片、3 段视频和 3 段音频。官方强调 Context-IR 对复杂多参考理解非常关键。
   - https://github.com/MiniMax-AI/MiniMax-H3
2. 官方 Ref2VA 提示词必须使用六段固定结构：`subject_definitions`、`summary`、`retention_analysis`、`detailed_description`、`overall_soundscape`、`non_diegetic_music`。
   - https://huggingface.co/MiniMaxAI/MiniMax-H3/blob/main/docs/VIDEO_PROMPT_WRITING_GUIDE_ref_en.md
3. `<Picture N>` 用于具体首帧、关键帧、末帧或构图锚；只提供人物、场景、服装或风格的图片应定义为来自相应 Picture 的 `<Subject N>`。
4. 具体关键帧任务应在 `summary` 中声明 `[keyframe completion]`；对白应使用稳定 speaker ID 和 `<d>[Language] ...</d>`；`retention_analysis` 使用固定关系标记。

## 社区中发现的同类问题

1. 有用户报告 Ref2VA 会把原本只用于参考的第一张图当成首帧；社区普遍强调必须严格使用官方语法，否则仍会出片但更容易出现异常。
   - https://www.reddit.com/r/StableDiffusion/comments/1vfonwv/you_can_use_images_specifically_as_references_in/
2. 单张末帧无法完整携带房间布局、物体位置、正在进行的动作和音频状态，这与本项目的跨门/房间拓扑问题相同。
   - https://www.reddit.com/r/HailuoAiOfficial/comments/1w57vv9/best_way_to_extend_minimax_h3_videos/
3. ComfyUI PR #15439 增加了 MiniMax H3 任意时间点 Guide：静帧或短帧序列可以按 `frame_idx` 注入，而不只是首尾帧。
   - https://github.com/Comfy-Org/ComfyUI/pull/15439
4. Motion Context 社区工作流把上一段视频的末尾潜变量直接注入下一段，重点解决跨片段运动、方向和音频连续性，并减少解码再编码造成的漂移。
   - https://github.com/seitanism/ComfyUI-H3-Motion-Context-MultiRef
5. Hybrid Image + Reference 工作流同时让 Qwen3-VL 看见首尾帧，并把帧的 VAE latent 注入 DiT；其作者指出，仅 Add Guide 而文本编码器看不到关键帧时，可能出现颜色漂移、扭曲和不自然过渡。
   - https://github.com/BigStationW/ComfyUi-MiniMax-H3-Image-And-Reference-To-Video
6. 对必须逐帧遵循空间路径的动作，社区已采用 H3 Fun ControlNet，以深度、Canny、Pose、HED 或 MLSD 控制视频逐帧驱动结构。这比普通参考图更确定，但需要额外节点和匹配权重。
   - https://github.com/wyzborrero/ComfyUI-H3-FunControl

## 提示词审计

早期 6 秒测试提示词语义明确要求女主跨门，时长也足够，但格式不完全合规：

- 使用了错误字段 `detailed_timeline`，正确字段是 `detailed_description`；
- `summary` 没有 `[keyframe completion + reference generation]` 前缀；
- `retention_analysis` 没有使用 `fully_preserved` 等固定标记；
- 没有 `[Shot 1]` 标记；
- 对白没有写成 `<d>[Chinese] 有人在找我。</d>`。

房间图片实际已作为 `<Subject 2>` 的来源引用；先前口头说它被错误定义成独立 Picture 并不准确。真正的问题是整体字段和关系格式未完全遵循官方指南。

新的双状态、合规单状态和下一镜接续提示词均按本地 `h3-prompt-writing` 技能及官方 Ref2VA 指南重写。

## 本地实验矩阵

| 实验 | 关键变化 | 结果 |
| --- | --- | --- |
| 原分镜 4 | 无状态锚 | 两人被放到走廊，拓扑错误 |
| 源状态锚，seed 42/43/44 | 上一镜截图 + 旧结构提示词 | 初始门口关系稳定，3/3 未跨门 |
| 单动作/动态锚 | 减少动作或缩短初态约束 | 均未跨门 |
| 房间参考 + 6 秒 | 增加目的地房间语义，旧结构提示词 | 女主沿走廊离开 |
| 合规单状态，seed 42 | 官方六段结构，无目标状态图 | 仍未建立明确二人房内末态 |
| 合规双状态，seed 42 | 源状态 + 人工审核的房内目标状态 | 连续跨门成功 |
| 合规双状态，seed 43 | 只改变 seed | 连续跨门成功，当前 2/2 |
| 分镜 5 接续，seed 42 | 使用上一实验 5.5 秒实帧 + 同一房间/人物 | 开场构图连续，女主在同一房间关闭同一扇门 |

双状态成功证明普通 Ref2VA 在本项目可用；合规单状态失败则说明格式修正不是充分条件，目标状态图是关键增量。当前样本量仍小，不能把 2/2 等同于所有剧集的稳定成功率。

## 推荐的通用生产流程

1. 对门、电梯、车辆、递物、坐下/起身、人物换位等“状态拓扑变化”自动标记为高风险分镜。
2. 为高风险分镜同时准备源状态图和目标状态图；两张图必须明确展示人物位于边界哪一侧。
3. 用官方六段 Ref2VA 结构编译提示词。具体状态帧用 `<Picture N>`，环境和人物只作为 `<Subject N>`。
4. 先用普通 Ref2VA 双状态生成 2–3 个候选，并审核：起始状态、真实动作路径、目标状态、身份和场景一致性。
5. 选择合格视频的稳定末态帧作为下一分镜开场状态锚，同时继续携带相同环境和人物参考。
6. 普通双状态无法稳定通过时，升级为带 `frame_idx` 的 Add Guide 或 Hybrid Image + Reference；需要连续速度和音频时使用 Motion Context；需要精确人物路径时使用 Depth/Pose/Canny 控制视频。
7. 不把“提示词中写了进入房间”视为成功证据，必须进行视觉状态审核。

## 当前本地能力差距

本机 ComfyUI 为 0.33.1，但当前节点清单没有 `MiniMaxH3AddGuide`。现有 `MiniMaxH3ReferenceToVideo` 只提供普通参考图片/视频/音频输入，没有关键帧 `frame_idx`；当前 Director R2V 也未接入 Motion Context。因此现阶段可先落地普通双状态方案，后续再评估升级 ComfyUI/Director 工作流。
