# RunningHub RH剧场逆向产品需求文档

> 文档性质：基于登录态实机页面、历史任务、已有截图和公开前端行为重建的产品需求参考，不是 RunningHub 官方文档。
>
> 调查时间：2026-09-05 至 2026-09-08。
>
> 目标：理解一个成熟 AI 短剧平台如何把“剧本—资产—分镜—视频—成片”组织成可控、可追溯、可计费的生产流程，并据此设计 LocalMiniDrama 的下一代产品架构。

## 1. 产品定义

### 1.1 产品定位

RH剧场是 RunningHub 体系中的 AI 漫剧/短剧生产产品。它不是单点生图或生视频工具，而是以“项目—剧集—场次—镜头”为生产骨架，连接剧本解析、资产设定、镜头生成、成片审核、资产复用和消费管理的项目制工作台。

核心价值主张可以概括为：

1. 从想法、剧本或已有视频进入创作，不要求用户从同一入口开始。
2. 把角色、场景、道具和风格从提示词片段升级为可复用资产。
3. 用分阶段门禁控制下游生成，减少上游反复变化导致的浪费。
4. 让每个生成动作在执行前显示模型、规格和价格，在执行后进入历史与消费明细。
5. 让单镜生成、局部修复、整集审片和发布形成闭环。

### 1.2 目标用户

| 用户 | 首要目标 | 典型痛点 | 产品响应 |
|---|---|---|---|
| 个人短剧创作者 | 快速从故事产出可发布短片 | 不懂复杂工作流、预算有限 | 四阶段向导、预设风格、批量生成、明码标价 |
| AI 导演/剪辑师 | 精确控制镜头、角色一致性与节奏 | 单次生成不可控、连续性差 | 分时码提示词、资产引用、站位图、历史候选、片段重拍 |
| 工作室制片 | 管理多集、多角色和成本 | 资产重复、进度不可见 | 项目/剧集分层、跨项目素材、消耗看板、团队空间 |
| 已有内容运营方 | 把旧视频转成新画风 | 重制成本高、批量处理困难 | 视频重绘项目、按集文件规范、统一画风与规格 |

### 1.3 核心成功指标

建议用以下指标衡量这一类产品，而不是只看“生成次数”：

- 首个项目从创建到完成第一张角色图的转化率。
- 剧本确认后进入设定、分镜、短片各阶段的漏斗。
- 单镜首次生成被选用率与平均候选次数。
- 引用缺失、模型能力不兼容和余额不足导致的生成前拦截率。
- 失败任务占比、失败不扣费正确率、任务恢复成功率。
- 资产跨集复用率与重复生图减少量。
- 从分镜确认到成片导出的中位时长。
- 单集实际费用相对生成前预算的偏差。

## 3. 端到端用户旅程

### 3.1 主路径

```text
选择创作入口
 → 创建项目并确定基础设置
 → 生成/解析剧本
 → 保存草稿
 → 确认剧本版本
 → 提取角色/场景/道具
 → 生成并确认资产主版本/派生版本
 → 提取或导入分镜脚本
 → 为镜头绑定资产、音色、故事板、站位与参考素材
 → 编辑分时码提示词并选择模型规格
 → 单镜或批量生成候选视频
 → 短片阶段逐镜审片和连续播放
 → 局部重拍/增强/替换不合格镜头
 → 全镜完成后保存至成片
 → 项目详情下载或发布至短片剧场
```

### 3.2 三种入口

#### 有想法

- 用户输入故事脑洞或长文本，页面提供题材提示。
- 调查时点页面显示内容上限为 15 万字，面向小说/长篇素材；该数值属于产品快照，不作为本地实现的固定常量。
- 系统生成剧本，再进入“保存—确认—下游提取”。

#### 有剧本

- 支持粘贴、拖拽和文件上传。
- 已观察格式：txt、docx、md、xlsx。
- 系统解析集、场、角色和正文结构；解析不是最终批准，用户仍可编辑确认。

#### 有视频

- 跳转视频重绘，不强行经过剧本与资产阶段。
- 以文件名识别集数，支持文件夹/多个视频形成重绘项目。

## 4. 核心领域模型

### 4.1 实体层级

```text
Workspace
└─ Project
   ├─ ProjectStyleBinding
   ├─ Episode[]
   │  ├─ ScriptRevision[]
   │  ├─ Scene[]
   │  │  └─ Shot[]
   │  │     ├─ ReferenceBinding[]
   │  │     ├─ StoryboardAsset[]
   │  │     ├─ GenerationJob[]
   │  │     └─ VideoCandidate[]
   │  └─ FinalCut[]
   ├─ Character[]
   │  ├─ CharacterAppearance[]
   │  └─ VoiceProfile[]
   ├─ Location[]
   │  └─ LocationVariant[]
   └─ Prop[]
      └─ PropVariant[]
```

### 4.2 关键对象要求

#### Project

- 名称、简介、封面、项目类型、所属空间。
- 默认语言、画幅、分辨率、全局画风和生成偏好。
- 聚合剧集、项目素材、分镜视频、成片和消费。

#### Episode

- 集序号、名称、目标时长、当前阶段、完成度。
- 独立阶段门禁；同一项目不同集可以停留在不同阶段。
- 对项目级角色/场景/道具记录出镜范围。

#### ScriptRevision

- 原始内容、解析结果、版本号、保存状态和确认状态。
- “保存草稿”只创建/更新修订；“重新确认”使其成为下游基线。
- 上游改变后，下游资产和分镜应标记为可能过期，而不是静默覆盖。

#### Asset 与 Variant

- 角色、场景、道具均有稳定实体 ID。
- 主版本代表身份/空间/道具基准；派生版本表示服装、时间、天气、损坏、持有等剧情状态。
- 每个版本保存业务描述、生成提示词快照、参考素材、候选图、选用结果、模型与任务 ID。

#### Shot

- 镜号、场次、目标时长、排序、角色/场景/道具绑定。
- 分时码动作、对白、旁白、音效、运镜、连续性起点/终点。
- 故事板、分镜图、站位图、参考图片/视频/音频。
- 视频生成参数、候选历史、选用候选和后处理结果。

#### GenerationJob

- 目标对象、模型、Provider、能力参数、预估费用、实际费用。
- 原始输入、最终提示词、负向提示词、参考图映射和编译器版本。
- 状态、阶段、进度、错误分类、外部任务 ID、创建/开始/结束时间。
- 失败任务也保留快照，并保证实际扣费为 0 或给出明确计费原因。

## 5. 生命周期与状态机

### 5.1 单集阶段

```text
script_draft
 → script_confirmed
 → assets_in_progress
 → assets_confirmed
 → storyboard_in_progress
 → storyboard_confirmed
 → video_in_progress
 → ready_to_export
 → exported
 → published（可选）
```

门禁原则：当前阶段可以查看前序数据；未满足确认条件时，后续阶段入口禁用或回退到最近合法阶段。直接修改 URL 不能绕过门禁。

### 5.2 生成任务

```text
draft → compiling → validating → quoted → queued → running
                                             ├─ succeeded
                                             ├─ failed
                                             └─ cancelled
```

- `compiling`：生成最终提示词与引用注册表。
- `validating`：检查缺失资产、模型能力、时长、引用数量和内容模式。
- `quoted`：展示本次价格，批量任务展示合计。
- `queued/running`：允许刷新后恢复。
- `failed`：显示阶段、Provider 原因、是否扣费和可重试条件。

### 5.3 资产状态

```text
extracted → edited → generating → candidate_ready → approved
                                  ├─ rejected
                                  └─ stale
```

上游描述、全局画风或主参考图变化后，已生成结果不能被删除，但应进入 `stale` 或显示“基于旧版本生成”。

## 6. 功能需求

### 6.1 开始创作

#### 功能

- 三条入口并列呈现：有想法、有剧本、有视频。
- 入口卡片必须说明所需输入、预期输出和是否产生费用。
- 长文本输入展示字数上限与当前字数。
- 文件入口支持拖拽、点击和粘贴；解析前显示格式、大小与版权提示。

#### 验收

- 用户能在一次页面访问内判断自己应走哪条路线。
- 无内容时主按钮禁用并解释原因。
- 解析失败不创建半成品项目，或明确标记为可恢复草稿。

### 6.2 项目与剧集管理

#### 功能

- 项目列表支持剧本项目/重绘项目/我的发布、搜索和排序。
- 项目卡显示封面、名称、集数、更新时间和更多菜单。
- 项目详情允许修改名称、封面、简介，新建剧集并查看各集当前阶段。
- 我的图片、分镜视频和成片按剧集筛选，支持批量下载。
- 发布按钮只在存在合法成片时可用。

#### 验收

- 每集进度相互独立；切换剧集不会丢失当前编辑上下文。
- 删除、发布、重命名等外部状态变更有明确确认和结果反馈。
- 项目级资产在不同集间复用时仍能追踪出镜范围。

### 6.3 剧本阶段

#### 页面结构

- 顶部：项目返回、项目名、剧集选择、四阶段步骤条、余额和账户。
- 左栏：分场大纲、场次数量与字数、正文定位。
- 中栏：剧本正文编辑器。
- 底部：保存草稿、重新确认剧本。
- 右下：项目 AI 会话入口。

#### 业务规则

- 保存和确认必须分开。
- 确认时计算本修订相对已确认版本的影响范围。
- 下游已有内容时，重新确认前展示：新增/删除/修改场次，可能失效的资产和分镜数量。
- 不允许用“正文非空”代替“业务已批准”。

#### 验收

- 保存后刷新能恢复文字和当前修订。
- 未确认的修订不会静默改写下游。
- 重新确认后产生可追踪的新版本，并让受影响对象进入待复核或过期状态。

### 6.4 设定阶段

#### 资产总览

- 场次筛选；角色/场景/道具统计标签。
- 标准模式与自由模式切换，共享同一数据源。
- 重新提取、批量生成、全局画风、画布编辑。
- 资产卡展示图片、名称、主配角/类型、关键操作和生成状态。

#### 角色

- 结构化字段：性别、年龄、身份、性格、外貌、服装。
- 主形象与变装；出镜集数和场次；音色配置。
- 素材参考图、AI 生成、本地上传、候选选择、确认、下载、任务追溯。
- 生成参数：图片模型、画幅、分辨率、预设类型、局部画风、费用。

#### 场景

- 主场景与衍生场景；地点、时间、天气、氛围、空间结构。
- 支持普通图、全景、俯视或产品定义的空间视图。
- 出镜范围、参考图、候选、确认、下载与任务追溯。

#### 道具

- 主道具与衍生状态；形制、材质、颜色、剧情用途。
- 支持封闭/开启/损坏/持有等状态，避免把派生图当作无语义候选。

#### 画风

- 官方预设与我的风格；真人/3D/2D 分类和搜索。
- 全局画风在项目/剧集层继承，单资产可跟随或覆盖。
- 预设应保存稳定 ID、描述、提示词、推荐模型和版本。
- 切换画风不追溯修改历史结果，但会影响后续重新生成。

#### 音色

- 智能音色设计、音色库、本地上传、提取音色四类入口。
- 音色预览与绑定分开；角色卡显示当前音色和试听。
- 智能设计生成前展示单次费用。

#### 批量生成

- 可多选资产；统一选择模型、预设和尺寸；展示数量与总价。
- 已有确认结果默认跳过，除非用户显式选择重做。
- 批次内每个资产独立记录状态，部分失败可单独重试。

### 6.5 分镜阶段

#### 集级工具

- 场次筛选、场次/镜头/预计时长统计。
- 重新提取、导入分镜脚本、批量生成。
- 批量产物至少区分：故事板、分镜图、站位图、视频。

#### 单镜检查器

- 镜号和目标时长。
- 出镜角色、角色状态、音色；场景和场景变体；道具与道具状态。
- 故事板、分镜图、站位图。
- 额外参考图片、视频和音频。
- 2D 画板与 3D 导演台入口。

#### 提示词编辑器

- 以分时码段组织动作、表演、构图、镜头运动、对白与声音。
- `@` 引用以芯片展示，文本与实际参考表建立稳定映射。
- 引用状态显示 `ready/stale/missing/text-fallback/incompatible`。
- 模型、画幅、分辨率、时长和模型特有开关动态联动。
- 生成按钮旁展示实时价格；不兼容时在生成前说明具体原因。

#### 镜头轨道

- 选择、前后插入、删除、合并和重新排序镜头。
- 合并后超过模型时长上限时禁用并解释。
- 镜头卡显示时长、状态、主缩略图和错误标记。

#### 导入分镜脚本

- 支持 xls/xlsx/docx 等可解析格式。
- 解析预览展示新增、覆盖、合并和字段缺失。
- 自动合并短镜头时只调整时长组织，不静默改写剧情内容。

### 6.6 2D 画板与 3D 导演台

#### 2D 画板

- 选择、画笔、矩形、直线、橡皮、填充、文字、图片。
- 图层、撤销/重做、缩放/适应、保存工程、截图。
- 输出角色为 `composition_previs`，不是正式分镜图。

#### 3D 导演台

- 自由视角/机位视角、标准方位、相机重置、FOV、相机距离。
- 场景环境图/全景球、地面网格、高度和透明度。
- 对象、灯光、机位、画幅、截图、录制与工程保存。
- 输出站位、构图、机位和运动参考，不承担完整 3D 动画制作。

### 6.7 视频生成与后处理

#### 生成

- 支持单镜与批量，批量可按 Provider 限制选择串行/并行。
- 生成前完成引用、能力、真人内容、余额、时长和价格预检。
- 创建任务后展示排队、运行、成功/失败、取消和重试。
- 每镜保留多个候选、选用状态和历史；重试默认复用原快照。

#### 后处理

- 截屏并沉淀为连续性参考。
- 片段重拍、裁剪、拆分、恢复、变速和排序。
- 高清修复、去字幕、画质增强、人声增强、提取伴奏。
- 后处理结果形成新版本，不覆盖原视频。

### 6.8 短片阶段

- 顶部显示当前镜头、总镜头和完成数。
- 主播放器审看选中候选，支持快退、播放、快进、音量和全屏。
- 全集时间线按场次和镜头顺序展示；完成与未完成状态明显区分。
- 连续播放按时间线播放所有已完成/已选用镜头。
- 所有必需镜头具备已选用视频后，才允许保存至成片。
- 保存至成片创建独立任务；成功后进入项目详情“我的视频—成片”。

### 6.9 资产库

- 官方素材库、项目素材、我的素材三层来源。
- 角色/场景/道具筛选、搜索和分页。
- 素材包可以包含主版本和多个派生版本。
- 导入项目时复制绑定关系或建立引用快照，避免源素材删除导致项目不可复现。

### 6.10 工具箱

- 脱离四阶段主流程，支持快速图片/视频生成。
- 允许引用本地或资产库中的图片、视频和音频。
- 提示词支持 `@` 引用、优化、智能识别和全屏编辑。
- 片段可组成轻量时间线并保存为成片。
- 工具箱产物应能回流项目/素材库，而不是形成孤岛。

### 6.11 视频重绘

- 支持文件夹或视频上传，格式 MP4/MOV，展示大小和时长限制。
- 文件名包含集数规则；上传前做版权提示。
- 设置语言、画幅、分辨率和目标画风。
- 创建独立重绘项目，进入批量处理、审核、下载流程。

### 6.12 AI 项目会话

- 四阶段页面常驻入口，能够读取当前项目、剧集、资产和任务上下文。
- 支持历史会话与连接状态。
- 回答和建议不应直接修改项目；修改类建议先生成可审阅草稿或差异。
- 会话记录要标明使用的数据版本，避免引用过期剧本或资产。

### 6.13 消费、钱包与合规

- 生成动作前显示单次/按秒价格；批量动作显示总价。
- 消耗看板提供时间、流程和项目筛选；总额、图片/视频次数、趋势、环节分布、项目排行和任务明细。
- 任务明细包含项目/剧集、类型、模型、状态、预估、实际消耗和失败原因。
- 失败不扣费的规则必须由账单记录验证，而不是只靠前端文案。
- 水印设置承担 AI 内容标识合规；发布前再次校验。
- 团队空间应区分成员、资产和消费归属；本次未验证具体权限矩阵。
- 账户面板聚合余额/充值、消耗看板、团队入口、水印设置、新手指引、邀请码、客服和消息通知；跳转主站或外部知识库时必须明确目标域与打开方式。

### 6.14 发布与短片剧场

- 首页展示社区作品的集数、时长、播放、点赞、作者和日期。
- 发布必须选择合法成片、封面、标题和简介，并通过水印/版权检查。
- 发布、点赞、评论等对外动作属于代表性行为，必须有显式用户确认。
- 发布版本与后续项目编辑隔离，历史公开作品不能被项目内无意改写。

### 6.15 实测能力与约束快照（2026-09-08）

下表用于还原调查时点的产品完整度与表单设计。它是证据快照，不是推荐 LocalMiniDrama 硬编码的长期配置；模型、价格、配额和格式应由能力注册表或后台配置驱动。

| 场景 | 实机观察值 | 产品设计含义 |

| 有想法 | 文本上限 15 万字 | 长文本要有字数计数、超限提示和可恢复草稿 |

| 图片预设 | 角色三视图、角色人设图、角色单图、我的自定义 | “产物用途”应是一等字段，而非只存在于提示词中 |
| 图片计价 | 样例约 ¥0.1/次至 ¥0.8/次 | 价格与渠道/模型联动；这里只证明前置报价交互存在 |

## 7. 跨模块系统需求

### 7.1 Provider 能力注册表

每个模型至少声明：输入模式、最大参考图/视频/音频数量、支持时长、分辨率、画幅、真人模式、首尾帧、续画、原生音频和并发上限。UI 只展示当前模型可用的控件，禁止用一张固定表单伪装所有模型一致。

### 7.2 提示词编译与快照

生成请求前固定：源业务描述、风格快照、最终提示词、负向提示词、引用注册表、模型能力、参数、编译器版本和哈希。快照必须与真正提交给 Provider 的输入逐字一致。

### 7.3 引用注册表

`@图片N` 只是展示序号，真正身份应是稳定资产/版本 ID。请求创建时产生确定性顺序，并同时保存“标签—资产—URL/文件指纹—用途”的映射。

### 7.4 任务可靠性

- 刷新后恢复进行中任务。
- 前端超时不等同 Provider 失败。
- 幂等创建，避免双击产生重复扣费任务。
- 任务结果落库失败与 Provider 失败分开分类。
- 重试可选择复用原快照或重新编译，并明确告知差异。

### 7.5 数据保护

- 删除、重新提取、重新确认和批量覆盖前先展示影响范围。
- 历史生成结果与当前配置分离。
- 用户上传文件、签名 URL、手机号和凭据不得写入普通日志或研究文档。

## 8. 非功能要求

- **可恢复性**：网络断开、页面刷新或桌面应用重启后，草稿与任务状态不丢失。
- **性能**：大型剧集只加载当前场次/镜头可见数据；图片使用缩略图与延迟加载。
- **一致性**：标准模式、自由画布和项目详情只通过同一领域 API 修改数据。
- **可观测性**：每个任务可按内部 ID、Provider ID、目标资产和编译版本追溯。
- **可访问性**：主要控件具备可读名称、键盘焦点、禁用原因和非颜色状态标记。
- **本地化**：中文/英文提示词和 UI 文案分开管理，风格名称与业务 ID 解耦。

## 9. 关键验收场景

1. 编辑已确认剧本后保存草稿，分镜不变化；重新确认时才展示并应用影响。
2. 切换项目全局画风，历史角色图不变；新生成任务使用新风格快照。
3. 某角色参考图失效，分镜显示 `missing/text-fallback`，付费生成前阻止或要求明确接受降级。
4. 将两个镜头合并后超过模型上限，生成按钮禁用并推荐可支持的模型/拆分方式。
5. 任务运行期间刷新页面，重新进入后仍显示准确状态和进度。
6. Provider 返回失败，任务保存最终输入、错误阶段和实际费用 0。
7. 所有镜头完成但某镜未选用候选，保存至成片保持禁用并定位问题镜头。
8. 成片导出成功后，可在项目详情筛选、下载；发布仍需独立确认。

### 已确认

- 三入口、项目/剧集/资产/工具箱/重绘/消费等全站信息架构。

- 剧本草稿与重新确认分离。

### 未验证

- 发布表单的完整字段、审核机制和撤回规则。

- 服务端数据库和隐藏提示词实现。
