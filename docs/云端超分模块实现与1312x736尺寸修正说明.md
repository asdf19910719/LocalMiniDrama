# 云端超分模块实现、调用流程与 1312×736 尺寸修正说明

日期：2026-09-05
适用项目：LocalMiniDrama

## 1. 本次结论

当前项目的 H3 视频实际生成尺寸是 `1312×736`。本次把云端超分生产契约统一为：

```text
1312×736 基础合并视频 → 2× 云端超分 → 2624×1472 画面
```

`1312×736` 的宽高都是 32 的倍数，MiniMax H3 节点能够合法处理，但它不是官方 0.98 MP 预设。官方 0.98 MP 档是 `1344×768`；`1280×736` 约为 0.9 MP。项目当前已有大量 1312×736 素材，因此本轮不重做 H3 镜头，而是让云端后处理与现有素材一致。

参考：[MiniMax H3 官方说明](https://huggingface.co/MiniMaxAI/MiniMax-H3/blob/main/README.md)、[ComfyUI 官方 H3 工作流模板](https://github.com/Comfy-Org/workflow_templates/blob/main/templates/video_minimax_h3_t2v.json)。

## 2. 原报错的真正原因

报错内容：

```text
云端超分工作流要求 1280×736，实际为 1312×736
```

这条错误发生在本地上传前，并不是云端 M19/M20 拒绝了视频。原实现的 `videoUpscalePlanner.validateSourceMedia()` 和 `video_upscale.expected_source_width` 把 1280 写成了固定值，所以 ffprobe 读到 1312 后立即终止，尚未上传文件，也没有产生云端推理费用。

远端模板复核结果：

| 工作流 | 读取节点 | 尺寸行为 | 本次处理 |
|---|---:|---|---|
| M20 FlashVSR | 195 | `custom_width=0/custom_height=0`，保留源尺寸；节点 192 指定放大倍率 | 每次提交时强制节点 192 `value=2` |
| M19 SeedVR2 | 25 | 保留源尺寸；节点 29 以短边目标和长边上限控制输出 | 每次提交时强制 `resolution=1472`、`max_resolution=2624` |

因此不需要先把 1312×736 裁剪、拉伸或缩放为 1280×736。适配器取得远端模板后，会在真正提交的完整工作流副本中写入正确尺寸；远端模板里的旧示例文件名和旧上限不会再决定生产输出。

本次也已把云端 ComfyUI 用户目录中的 M19 工作流副本从 `resolution=1472/max_resolution=2560` 持久化更新为 `1472/2624`，写入后回读校验通过。控制面板自己的内置工作流库没有提供上传或更新接口，且执行 `/api/workflows/initialize-comfyui` 时可能重新覆盖 ComfyUI 用户副本；因此生产正确性仍由提交适配器强制写入尺寸保证，而不依赖远端静态模板是否再次被覆盖。M20 用户工作流原本就是动态 2×，无需持久化修改。

## 3. 用户如何发起云端超分

在单集成片区域：

1. 选定各分镜的视频候选。
2. 开启“云端超分”（界面提示为 2×）。
3. 选择 `FlashVSR（推荐）` 或 `SeedVR2`。
4. 点击合成/最终成片。

前端调用：

```http
POST /api/episodes/{episodeId}/finalize
```

请求的合并选项包含：

```json
{
  "upscale": {
    "enabled": true,
    "method": "flash"
  }
}
```

`method=flash` 对应 M20；`method=seed` 对应 M19。不开启时保持原来的本地合并流程。

## 4. 合并后的完整业务流程

```text
选定分镜视频
  → FFmpeg 合并出 base_merged.mp4
  → ffprobe 校验 1312×736、fps、帧数、音轨
  → 创建持久化 video_upscale_job 与分段记录
  → 检查云端面板和 ComfyUI；必要时启动 ComfyUI
  → 基础视频只上传一次
  → 按 240 帧分段、相邻段重叠 4 帧
  → 每段读取 M19/M20 完整模板并写入视频、帧区间和目标尺寸
  → POST /api/workflow/generate 提交云端 prompt
  → 轮询结果并下载每个超分分段
  → 校验每段必须为 2624×1472、帧数和 fps 正确
  → 本地按帧裁掉重叠并拼接，恢复基础视频音轨
  → 校验最终尺寸、帧数、fps、时长和音轨
  → 在超分结果上添加字幕、水印和最终混音
  → 写回单集成片地址
```

超分位于“基础视频合并之后、字幕和水印之前”。这样只处理最终采用的镜头，且字幕、水印不会被生成式超分重绘。

## 5. 云端模板提交机制

项目不直接向原生 ComfyUI `/prompt` 发送一个固定 JSON，而是使用控制面板协议：

1. `GET /api/workflow/config/{workflowId}` 取得 `workflow_template`。
2. 深拷贝模板并移除根级 `_api_config`。
3. 严格修改已知节点；缺少节点或字段就返回 `WORKFLOW_SCHEMA_CHANGED`，不提交推理。
4. `POST /api/workflow/generate`，提交完整模板和稳定的 `client_id`。
5. 使用 `prompt_id` 查询结果，下载视频输出。

M20 每段会修改节点 195/204/192；M19 每段会修改节点 25/27/29。目标宽高从已经持久化的作业记录传入，不依赖文字提示或示例文件名。

## 6. 长视频分段和恢复

默认每段 240 帧、重叠 4 帧。例如 241 帧会规划为：

```text
第 1 段：start=0，count=240，trim=0
第 2 段：start=236，count=5，trim=4
```

拼接时按帧裁掉第二段开头的 4 帧，因此最终仍是 241 帧。若发生 OOM，未完成区间按 `240 → 120 → 60` 降低分段长度；已完成段不会重算。

作业、分段、远端 `prompt_id`、下载结果和输出路径都写入 SQLite。服务重启或下载失败后会查询已有 prompt，不会因为恢复流程重复提交已经完成的推理。

## 7. 失败与人工操作

- 云端关机或暂不可达：合并任务进入 `waiting_upscale`，基础视频保留。
- `retry`：复用已有作业、prompt 和下载检查点。
- `skip`：仅在失败或等待云端时可选，明确使用 1312×736 基础视频继续最终化。
- `cancel`：结束本地最终化并保留基础视频；已经提交的远端 prompt 可能仍继续运行。
- 输入不是 1312×736：上传前返回 `UNSUPPORTED_SOURCE_DIMENSIONS`，不会偷偷拉伸。
- 云端模板节点变化：上传后、提交推理前返回 `WORKFLOW_SCHEMA_CHANGED`。

## 8. 当前配置

```yaml
video_upscale:
  enabled: true
  provider: zealman
  default_method: flash
  workflows:
    flash: M20-视频高清放大-FlashVSR-2倍-分段工作节点
    seed: M19-视频高清放大-SeedVR2-2倍-分段工作节点
  expected_source_width: 1312
  expected_source_height: 736
  scale: 2
  segment_frame_cap: 240
  overlap_frames: 4
```

派生目标尺寸为 `2624×1472`。能力接口 `GET /api/v1/video-upscale/capabilities` 会返回当前源尺寸、目标尺寸、工作流可用性和云端状态，该接口只读且不会触发 GPU 推理。

## 9. 本次修改点

- `videoUpscaleConfig.js`：默认源宽改为 1312。
- `videoUpscalePlanner.js`：上传前按 1312×736 校验，派生 2624×1472。
- `videoUpscaleJobService.js`：把持久化目标宽高和倍率传给每个云端分段。
- `zealmanUpscaleClient.js`：M20 写入 2× 倍率；M19 写入 1472 短边和 2624 长边上限。
- `config.yaml`：当前部署配置改为 1312×736。
- `FilmCreate.vue`：界面说明改为 1312×736 → 2624×1472。
- 后端和前端回归测试同步覆盖新契约。

自动化测试验证本地预检、目标尺寸派生、云端模板变换、作业参数传递、分段、恢复、拼接和界面文案。读取云端 M19/M20 模板确认节点仍存在，并将 ComfyUI 用户目录中的 M19 副本更新为 `1472/2624`；这些操作都不会排队执行推理。本次没有提交新的真实 GPU 推理，避免未经单独确认产生费用。首次生产实跑后应核对：

- M19 没有被 `max_resolution=2560` 再次限制；
