# Production Studio V2.1 分镜页重设计（RunningHub 式五区布局）

日期：2026-09-10
状态：已确认（替代 2026-09-08 交互规格第 8 章与 STORYBOARD-020 的三栏四区方案）
范围：`production-studio-v2.1-full-prototype.html` + `-model.js` + `.test.cjs`，及交互规格、决策记录、E2E 验收矩阵、设计评审的同步。产品代码（frontweb）不在本次范围。

## 1. 背景与目标

STORYBOARD-020 将旧分镜原型重排为“当前镜头优先”的三栏工作台，但仍保留 6 个正交 UI 维度
（左栏 4 区 × 媒体 2 模式 × 辅助 4 视图 × 右栏 3 标签 × 镜头 × 场景 17 种）、7 个抽屉入口、
双重时长（计划 7s/请求 8s）与三段耗时预估。评审结论：作为开发基线仍过于复杂。

本次重设计以 RunningHub 分镜页（`docs/research/_artifacts/runninghub-survey-2026-09-08/03-分镜页-三栏编辑器.png`）
为布局基准，以当前项目版本（`frontweb/src/views/FilmCreate.vue` 分镜卡片：素材绑定 / 分镜图历史条 /
视频历史与候选 / 尾帧衔接）为交互素材，重建分镜页。

核心目标（用户确认的需求清单）：

1. 分镜内直接展示**可编辑的时段提示词**，并与**对应生成的分镜视频**同屏工作。
2. 展示和选择**剧集素材**（角色含人物状态、场景、道具）。
3. 支持**生成分镜图**（候选 + 历史）。
4. 本项目特有：**生成 H3 提示词**、**用 H3 生成视频**（H3 一等公民，不再折叠进高级设置——此点推翻 09-09 简化设计 §7.4 的“H3 下沉高级设置”决策）。
5. **视频候选**与**视频生成历史记录**。
6. **不同分镜切换**（上一镜/下一镜 + 底部镜头轨 + 下拉）。

## 2. 五区布局

```
┌ 页头：阶段导航（剧本→设定→分镜→成片）＋ 异常状态条（仅异常场景显示）
├ 工具栏：场次 ▾ · 镜头 ▾ · ‹上一镜｜下一镜› · x/y 已采用 ‖ 批量生成 · 更多▾
├────────────┬──────────────────────────────┬────────────────┤
│ 左：镜头检查器 │ 中：时段提示词工作台（核心）        │ 右：结果与生成     │
│ · 镜头号/时长 │ · 引用素材 chips（@图片N）         │ · 分镜图｜视频 tab │
│ · 出场角色   │ · 时段卡（时码+画面动作+对白声音     │ · 主预览          │
│   （人物状态）│   可编辑/拆分/合并/上移/下移）      │ · 候选条          │
│ · 分镜场景   │ · H3 提示词条（状态芯片+生成按钮      │ · 用于本镜/撤销/重试│
│ · 场景道具   │   +可折叠可编辑草稿）              │ · 历史（含失败任务） │
│ · 首尾帧衔接 │ · 生成条：[生成分镜图] [用 H3 生成视频 ¥x] │              │
├────────────┴──────────────────────────────┴────────────────┤
│ 底部镜头轨：筛选 · 逐镜缩略卡（图/视频状态）· 进入成片审核（x/y）        │
└─────────────────────────────────────────────────────────────┘
```

输入（左＋中）与输出（右）分离，与 RunningHub 一致；同一镜头的所有状态一屏可见。

## 3. 保留的交互契约（不回退，来自 E2E 验收）

- 生成前联合检查 4 项（引用素材 / 模型能力 / 生成描述 / 重复任务）：不满足时禁用生成按钮并逐行展示，不再用报错弹窗。
- 视频成功只追加候选，不自动采用；候选必须先载入主播放器才可“用于本镜”；采用指针全镜唯一，可撤销。
- 改选当前分镜图 → H3 草稿标记“需要更新” → 已采用旧视频标“基于旧分镜图”并退出完成计数；重新生成 H3 后恢复。
- H3 草稿状态机：`ai-generated → dirty → saving → valid/invalid`；来源变化 → `stale`；dirty/saving/stale/invalid 全部阻止视频提交；永不覆盖人工文本。
- 失败重试创建新任务；取消进入 `cancel-requested` 并保留任务记录。
- 视频提交前费用确认（确认抽屉显示费用与预计耗时）。
- 分镜结构更新 / 导入：预览差异 → 创建新版本，不直接覆盖，媒体历史保留。
- “进入成片审核（x/y）”允许提前审片（软进入），“开始合片”仍要求全部镜头采用。

## 4. 移除的复杂性（本次的核心简化）

| 移除项 | 处理 |
|---|---|
| 左栏 4 区切换（镜头描述/引用/时段/连续性） | 左栏改单列检查器；时段编辑升入中栏；镜头描述并入时段（第一时段即本镜意图） |
| 辅助视图（站位图/连续性/动作预演） | 从分镜页移除；连续性简化为左栏“首尾帧衔接”一行（上一镜尾帧→本镜首帧） |
| 右栏 3 标签（设计/生成/历史） | 右栏单列：结果与生成一屏展示 |
| promptCompiler.sections（业务意图/动作运镜/负向约束/编译结果） | 删除；时段 + H3 草稿即生成描述 |
| Recipe / Reference Manifest / AV contract / Universal mode / fingerprint 展示 | 从页面删除 |
| 双重时长（计划 7s/请求 8s） | 单一“输出时长 7s” |
| 三段耗时预估（排队/处理/总耗时） | 单行“预计 5–10 分钟”；候选保留完成时间 |
| 局部重拍 | 移除（历史 + 按原输入重试已覆盖诉求） |
| 批量抽屉 6 项 | 简化为 3 项：生成缺失分镜图 / 生成缺失视频 / 重试失败项 |
| 场景 17 种 → 12 种 | 删除 stale / multi-segment / prompt-gate-failed / continuity / candidate-compare；保留 loading、empty、blocked、save-failed、conflict、provider-blocked、h3-stale、h3-invalid、video-generating、generation-failed、batch-partial |
| UI 状态 6 维 → 1 维 | `storyboardUiState = { key, page, mediaMode }` |

结构更新 / 导入 / 导出 / 批量 / 高级画布收进工具栏“更多”菜单（入口仍存在，不再占据工具栏主位）。

## 5. H3 一等公民

- 中栏 H3 条：状态芯片（AI 生成 / 已编辑 / 保存中 / 校验通过 / 校验失败 / 需要更新）＋「生成 H3 提示词」按钮＋可折叠草稿编辑器（默认折叠一行，展开后可编辑、保存并校验）。
- 生成条主按钮「用 H3 生成视频」由 H3 草稿状态 + 联合检查共同驱动；不可用时禁用并显示原因。
- 模型层将 H3 草稿提升为 `page.h3Draft`（原 `promptCompiler.h3Draft` 外壳删除）。

## 6. 模型层要点

- `page.layout = ['shot-inspector', 'segment-prompts', 'result-and-generation']`。
- `page.inspector`：characters（含人物状态）/ scene / props / frameChaining（首尾帧衔接）。
- `page.segmentEditor`：referenceChips（@图片N ↔ 素材）、segments（复用现有拆分/合并/重排/自动保存命令）。
- `page.resultPanel`：mediaMode（image|video）、image（currentId/candidates/activeTask/channel）、video（adoptedId/candidates/activeTask/gate/outputDuration/estimatedCost/estimatedTime）。
- 新命令 `selectStoryboardShotByStep(page, direction)`：按全集镜头顺序上一镜/下一镜，边界抛错。
- 恢复参数简化为 `scene / shot / tab(image|video) / candidate`；`inspector` 参数从分镜页恢复位置移除（通用序列化器不变）。

## 7. 验收口径（同步到 E2E 矩阵 §E/§G）

- 分镜页 HTML 不再出现：站位图、动作预演、辅助视图、Reference/Provider 技术详情、预计排队/预计生成处理/预计总耗时、计划时长 vs 请求时长双字段。
- 分镜页必须出现：时段提示词编辑器（可编辑）、引用素材 chips、生成分镜图、生成 H3 提示词、用 H3 生成视频、视频候选与历史、上一镜/下一镜、底部镜头轨、进入成片审核（x/y）。
- 上述交互契约（§3）全部保持。

## 8. 评审修订（2026-09-10 当日，用户确认）

用户在浏览器中评审第一版五区布局后提出四点，全部采纳：

1. **分镜图候选迁到左栏**：对齐 RunningHub 的 `故事板 | 分镜图` 标签位——分镜图是"输入"，与素材同栏；左栏底部新增分镜图区（当前图与候选缩略横排 + `生成分镜图` / `上传图片` 入口）；点击缩略图打开大图预览抽屉（含该图使用的图片提示词与"设为当前分镜图"）；上传直接进入候选。中栏生成条只保留 `用 H3 生成视频`。
2. **右栏改为视频专属大区域**：移除分镜图|视频切换，右栏即视频审核；栏宽从 340px 加大到 420–480px，主预览最小高度从 300px 提到 360px；生成历史从常驻小节改为面板头按钮打开抽屉。
3. **素材行可点击预览**：出场角色、分镜场景、场景道具每行可点击，打开素材预览抽屉（大图、类型、本集状态、`@图片N` 槽位说明）。
4. **补分镜图提示词**：中栏新增"分镜图提示词"折叠行——默认按"时段画面描述 + 引用素材 + 项目风格"自动拼装，可直接编辑（标记 `已手工覆盖`，自动拼装不再覆盖），可一键恢复自动拼装；生成分镜图确认抽屉展示本次使用的完整提示词。

恢复参数相应简化为 `scene / shot / candidate`（`tab` 参数随媒体模式概念移除）；`resultPanel` 收缩为视频播放器状态（`mediaMode`/`previewImageCandidateId` 字段删除）；新增模型命令 `editStoryboardImagePrompt` / `resetStoryboardImagePrompt` / `uploadStoryboardImage` / `getStoryboardAssetPreview`。

## 9. 二次评审修订（2026-09-10，用户确认）

用户指出三处交互缺口，全部采纳：

1. **管理镜头引用成为真实操作**：`管理镜头引用` 从纯文字说明抽屉升级为管理抽屉——按出场角色 / 分镜场景 / 场景道具三组列出（名称、固定版本状态、移除按钮），每组提供从项目素材目录添加的入口（已在本镜的素材不重复出现）。本镜场景是结构性的，不可移除。任何增删即时重排中栏引用 chips、将 H3 草稿标记为 `引用已变化`（需重新编译），并同步刷新自动拼装的分镜图提示词（手工覆盖的不动）。新增模型命令 `getStoryboardReferenceManager` / `removeStoryboardShotReference` / `addStoryboardShotReference`。
2. **素材预览展示版本与使用位置**：预览抽屉在类型/状态/槽位之外，新增版本信息（本集固定版本、素材库最新版本、是否可换绑）与 `出现时段`（该素材被哪些时段的提示词直接提及），并提供 `换绑到最新版`（仅当有更新时可用，换绑后 H3 与自动分镜图提示词标脏）与 `在素材库中查看` 两个操作。`getStoryboardAssetPreview` 返回值相应扩展 `version` / `latestVersion` / `canUpdateToLatest` / `usedInSegments` / `actions`。
3. **H3 生成视频可选择候选数量**：生成确认抽屉新增 `生成数量`（1 / 2 / 3，默认 1）选择，费用按数量乘算、耗时按并行提交口径展示。提交时一次创建 N 个并行任务（`activeTasks` 数组，`activeTask` 保持指向第一个任务以兼容既有消费方）；沿用"成功只追加候选、不自动采用"规则，取消逐任务执行。新增模型命令 `getStoryboardVideoBatchQuote`（数量钳制在 1–3，越界抛错），`submitStoryboardVideoGeneration` 增加 `{ count }` 参数。
