# 统一视频生成 Provider 架构设计

日期：2026-08-25

## 1. 背景与目标

当前视频生成存在两条彼此独立的调用链：普通模式、自由创作、批量生成和画布顶部工作流调用 `/videos`，由 AI 配置中的视频配置选择云端服务；画布右侧 AI Director 则绕过 AI 配置，直接调用固定的本地 ComfyUI 工作流 `h3-continuity-v1`。这导致相同的“生成视频”操作可能使用不同服务，任务、候选、产物和错误状态也不能保持一致。

本次改造的目标是建立唯一的视频生成能力抽象：所有入口只使用“API 配置 → 视频生成”中的唯一默认配置。ComfyUI 是标准视频 Provider 之一，不再是画布专属旁路。普通模式和画布模式共享相同生成能力、任务状态和候选数据，只允许页面布局不同。

## 2. 产品规则

1. 所有视频生成入口始终使用唯一、启用的默认视频配置。
2. 生成时不提供临时 Provider 切换。
3. 请求中的 `provider` 不参与路由；实际 Provider 由后端解析并记录。
4. 请求中的 `model` 只能选择默认配置自身声明的模型，不能借此切换配置。
5. 默认配置变更只影响新任务；运行中任务使用创建时的配置快照。
6. Provider 失败时不得静默切换到其他 Provider。
7. 普通模式与画布模式共享同一视频生成组件、接口和数据，功能必须一致。
8. 所有视频生成操作、状态、提示和错误使用中文。

覆盖入口包括普通影片模式、画布模式、画布批量工作流、一键生成、补全并生成、自由创作和 Director 候选生成。

## 3. 方案选择

采用“统一视频生成服务，保留 Director 候选评审能力”的方案。

所有入口调用统一视频生成接口，由后端读取唯一默认视频配置并分派到 Provider 适配器。ComfyUI、MiniMax、Seedance、Kling、Veo 及现有云端服务都遵守相同的任务契约。Director 不再决定生成引擎，只负责候选分组、QC、选择和连续性关系。

不采用以下方案：

- `/videos` 直接转发现有 Director：会长期保留两套任务和产物状态。
- 仅在前端按 Provider 分流：无法保证所有入口行为一致，并会继续复制路由逻辑。

## 4. 总体架构

```text
普通模式 ─┐
画布模式 ─┤
批量生成 ─┤
一键生成 ─┼─> 统一视频生成 API ─> 默认视频配置解析器 ─> Provider 适配器
自由创作 ─┤                                          ├─ ComfyUI
Director ─┘                                          ├─ MiniMax
                                                     ├─ Seedance
                                                     ├─ Kling / Veo
                                                     └─ 其他现有 Provider
```

统一服务负责配置解析、输入规范化、任务创建、状态转换、取消、重试、恢复、结果持久化和错误规范化。Provider 适配器只负责将统一请求转换为厂商或本地运行时请求，并把结果转换回统一状态。

## 5. API 配置

### 5.1 唯一默认配置

`service_type=video` 必须且只能存在一个启用的默认配置。生成前由后端执行严格校验：

- 没有默认配置：拒绝生成并返回“未配置默认视频生成服务”。
- 存在多个默认配置：拒绝生成并返回“存在多个默认视频配置”。
- 默认配置未启用：视为没有默认配置。

不再回退到第一条启用配置，也不再使用 `chatfire` 等硬编码默认值。

### 5.2 ComfyUI Provider

ComfyUI 作为标准视频配置保存：

- `service_type`: `video`
- `provider`: `comfyui`
- `base_url`: 默认 `http://127.0.0.1:8188`
- `model/default_model`: 工作流 ID，例如 `h3-continuity-v1`
- `api_key`: 可为空
- `settings`: 默认宽度、高度、帧率、Seed、连续性参数、工作流注册信息和显存策略

工作流 JSON、SHA-256、模型和自定义节点治理仍由现有 Director workflow registry 管理。AI 配置引用已登记的工作流，不复制 workflow JSON。

### 5.3 配置快照

创建任务时保存配置 ID及不可变快照，包括 Provider、协议、Base URL 的非敏感标识、模型或工作流、关键 settings 和版本。API Key 不写入任务快照。重试和恢复使用原快照；只有“按当前配置重新生成”才解析新的默认配置并创建新任务。

## 6. 统一请求与 Provider 契约

统一视频请求包含：

- 项目、剧集和分镜标识
- 提示词、负面提示词
- 首帧、尾帧和参考素材
- 宽度、高度、时长、帧率、Seed
- 连续性模式和锚点
- 候选数量

提示词默认优先级为：

1. `universal_segment_text`
2. `video_prompt`
3. `polished_prompt`
4. `image_prompt`
5. 分镜描述

Provider 适配器暴露统一能力：提交、查询、取消、恢复和能力描述。能力描述决定界面字段是否可用，但不能改变统一 Provider 选择规则。云端不支持的参数由适配器明确忽略或拒绝，并返回中文说明；不能悄悄转换成其他 Provider。

`/director/shots/:id/generate` 暂时保留为兼容入口，但必须调用统一视频服务，不能直接读取固定 ComfyUI URL或固定工作流。

## 7. 任务与候选数据

### 7.1 主任务

`video_generations` 成为所有新视频任务和最终媒体的主记录，保存：

- 分镜、剧集、项目和候选组关系
- 配置 ID与配置快照
- 实际 Provider、协议、模型或工作流
- 完整规范化输入
- 上游任务 ID或 ComfyUI Prompt ID
- 状态、进度、错误代码、错误详情和发生阶段
- 视频 URL、本地路径、媒体元数据
- 创建、开始、完成和取消时间

Provider、协议和模型由后端根据配置写入，不信任前端字段。

### 7.2 状态机

```text
等待中 -> 排队中 -> 生成中 -> 待审核 -> 已选用
                    ├-> 失败
                    └-> 已取消
```

状态转换由统一服务管理。Provider 适配器返回原始状态，统一服务负责映射和持久化。

### 7.3 候选组

一次请求生成一至三个候选，每个候选对应独立的 `video_generations` 主任务。`director_candidate_groups` 和 `director_candidates` 只保存分组、评审、QC、选用、选择原因及连续性关系。

即使候选数量为一，完成后也进入“待审核”，用户确认后才成为分镜当前视频，不能自动覆盖已有结果。未选候选保留为历史。

### 7.4 旧数据兼容

现有视频、Director Job、Artifact、候选和选择记录不删除、不重跑。迁移增加关联字段并允许旧记录继续读取。无法可靠确定实际 Provider 的历史记录标记为“历史来源未知”，不伪造来源。迁移必须幂等，并在执行前生成数据库备份。

## 8. 取消、重试与恢复

- 等待中、排队中和生成中的任务可以取消。
- ComfyUI 取消同时中断对应 Prompt。
- 云端支持取消接口时调用上游；不支持时标记本地取消并忽略迟到结果。
- 失败重试复用原配置快照、输入、Seed、模型或工作流版本。
- 已有上游任务 ID时优先继续查询，避免重复提交和重复计费。
- 后端重启后恢复未完成任务：ComfyUI 查询 Prompt 历史，云端继续查询原任务；无法恢复时标记“执行中断”并允许重试。
- “按当前配置重新生成”创建新候选组，不修改原任务。

## 9. 统一中文 UI

普通模式和画布模式使用同一个视频生成面板组件：普通模式以抽屉或对话框呈现，画布模式固定在右侧。两种模式均提供：

- 当前默认 Provider、模型或工作流及服务状态
- 提示词和负面提示词编辑
- 宽度、高度、时长、帧率和 Seed
- 候选数量
- 连续性模式和锚点选择
- 生成候选、排队状态、取消和重试
- 候选预览、QC、选用和候选组历史
- 完整中文错误摘要及可展开技术详情

所有现有英文文案改为中文，包括 AI Director 标题、创作/高级模式、生成候选、刷新、取消、重试、质量检查、选用、选择原因、连续性模式和 GPU 队列状态。

两种模式只能在布局和导航上不同，生成能力与数据不得不同。Timeline 是影片编排工具，可从两种模式进入；画布保留常驻入口。连续性锚点属于视频生成能力，两种模式都必须支持。

## 10. 分辨率

界面使用宽度和高度两个数字输入框，不使用“预览/生产/大师”等文本档位：

- 默认宽度：`1280`
- 默认高度：`704`
- 数字步进：`32`
- 可提供纯数字快捷值：`864 × 480`、`1280 × 704`

H3/ComfyUI 后端必须验证宽度和高度均为 32 的正整数倍。云端 Provider 使用自身尺寸规则，由相应适配器验证和转换，不能错误套用 H3 规则。现有 `1280×720` 和 `1920×1080` H3 选项移除。

## 11. 配置验证与错误处理

### 11.1 ComfyUI 测试连接

测试连接验证：

- Base URL、`/system_stats` 和队列接口
- 工作流 ID、状态和 SHA-256
- 必需模型和自定义节点
- 默认数字分辨率和显存预算

测试连接不启动真实推理。另设“生成测试片段”操作，只有用户明确点击才执行实际任务。

### 11.2 云端测试连接

验证 Base URL、鉴权、模型、创建端点和查询端点。优先使用无计费或最低成本接口；可能产生费用时必须先提示用户。

### 11.3 错误规范

用户界面显示中文摘要，例如未配置默认服务、多个默认配置、ComfyUI 无法连接、工作流校验失败、缺少模型、分辨率非法、显存不足、提交失败、查询超时和任务取消。技术详情保留 Provider 原始错误、任务 ID和失败阶段，并放入可展开区域。

## 12. 测试与验收

自动测试覆盖：

- 默认配置缺失、重复、禁用及切换
- `provider/model` 不能绕过默认配置
- ComfyUI 和云端适配器契约
- 数字分辨率及 H3 的 32 倍数规则
- 普通模式和画布共享组件、接口和候选数据
- 单候选、多候选、取消、重试、继续轮询和重启恢复
- 配置快照与运行中配置隔离
- 旧视频和旧 Director 数据迁移
- 视频生成 UI 中文文案扫描
- 后端、前端完整测试和前端构建

浏览器验收覆盖普通模式和画布的桌面/移动布局、跨模式任务一致性、API 默认配置切换后的全入口一致性、错误态、无横向溢出、无控制台错误和无重复提交。

真实推理控制成本：自动测试不启动 H3；最终仅执行一个 `864×480`、短时长、单候选的本地冒烟任务。`1280×704` 只完成配置和边界验证。长时间稳定性、真实音频验证和完整 benchmark 继续保留待办。云端真实生成不自动执行。
