## 1. 使用规则

1. 本文是“决策与理由台账”，不是新的架构母稿，也不是版本迭代记录；产品实现与验收仍以架构母稿、交互流程合同、状态真值表、UI 规格和 E2E 矩阵为准。
2. 每个结论使用稳定决策编号。后续修改不得悄悄覆盖旧结论；发生变化时保留原记录，标记为“已取代”，并填写替代决策编号。
3. 决策状态只有：`提议中`、`已确认`、`已取代`。只有用户明确采用的结论可以标记为`已确认`。
4. 每项记录结论、理由、影响范围、原型状态和产品代码状态。原型实现不等于产品代码已实现。
5. 每完成一个页面或流程的讨论，应在同一批修改中更新本文及对应权威规格；若两者不一致，以最新明确确认的决策为线索，先修正文档矛盾再开发。

## 3. 详细决策

### GLOBAL-001｜统一完整原型

- **状态**：已确认
- **结论**：建立一个完整原型入口，合并 Project Hub、项目详情、全局工具和四阶段 Studio。52 项产品能力都要有稳定 `data-feature-id`、可导航入口和可查看状态；78 项 E2E 继续作为独立验收矩阵，纯后端、迁移和并发规则不伪造成独立 UI 页面。
- **理由**：避免两套原型产生导航、状态和功能覆盖口径分裂，同时保留 UI 原型与后端验收的边界。
- **影响**：统一原型设计、实施计划、完整原型、截图目录以及功能—原型—E2E 对照。
- **落实状态**：统一壳、17 个注册页面和 52/52 功能覆盖导航已完成；纯模型测试与浏览器巡检已覆盖关键正常、异常和恢复路径。产品代码仍未开发。

### PROJECTS-001｜项目列表默认卡片视图

- **状态**：已确认
- **结论**：项目列表首次进入默认显示卡片视图；用户可切换列表视图，本地保存选择，刷新后恢复。
- **理由**：项目封面、四阶段摘要和任务/阻塞 badge 在卡片中更容易扫描；列表视图作为高密度备选。
- **影响**：项目列表布局、视图切换控件、本地偏好恢复。
- **落实状态**：统一原型与模型测试已实现。

### PROJECTS-002｜项目卡主交互

- **状态**：已确认
- **结论**：点击项目卡空白区域，或聚焦卡片后按 `Enter/Space`，进入项目概览；卡片上的“继续剧本/设定/分镜/短片”恢复真实最近工作位置。不得再放置与卡片落点相同的“项目详情”按钮。
- **理由**：消除两个相同落点造成的动作冗余，让唯一醒目按钮表达更有价值的“继续工作”。
- **影响**：项目卡鼠标与键盘行为、CTA 数量、无障碍标签。
- **落实状态**：统一原型、模型测试和 UI 规格已实现。

### OVERVIEW-001｜项目概览职责

- **状态**：已确认
- **结论**：项目概览只显示项目级下一步、四阶段聚合状态、Project Look 和可操作待处理项，不展开完整剧集列表或逐集操作。全部剧集与逐集四阶段状态统一由“剧集”页承载。
- **理由**：避免概览与剧集页形成重复事实源，保持概览适合快速定位和继续工作。
- **影响**：项目概览内容、项目详情导航、剧集页职责。
- **落实状态**：统一原型和 UI 规格已实现。

### DATA-001｜数据管理不作为日常创作主导航

- **状态**：已确认。
- **调研结论**：RunningHub RH 剧场当前可见结构及同类在线生成产品普遍把素材整理、历史和删除分散在项目菜单、资产区或文件区，没有把“数据管理”作为与概览、剧集、资产并列的日常创作页面。

6. 已确认版本之后的编辑派生新草稿；历史版本只读，可比较、复制为新草稿。
7. 空剧本、保存失败、版本过期、Diff 和冲突均保留内容并提供唯一恢复动作。
8. 原型演示不得写真实项目或调用收费模型。

### EP-ASSET-001～012｜剧集设定

采用第 4.1 节全部建议。本页只选择剧本实际引用的人物状态、场景状态/视图、道具状态和条件音色；项目资产负责生产和编辑媒体。项目 current 更新不静默改写本集选择；“进入分镜”一次完成预检、保存精确 version/hash/Look/音色的不可变快照并跳转。未满足必需项时按钮阻断，取消或事务失败不留下部分快照。

### AI-TASK-001～008｜AI 配置与任务

1. 配置分为全局默认、项目覆盖和任务不可变快照；用途到 Provider/模型的映射明确可见。
2. 密钥始终脱敏，配置导出不含密钥；导入冲突逐项选择，不做静默覆盖。
3. 连接测试只检查地址、认证、模型和 capability，不提交生成任务、不产生生成费用。
4. Provider capability 决定暂停、恢复、取消、重试和重排是否出现；不能显示虚假可执行动作。
5. 只有 Provider 提供可信进度时显示百分比；否则显示生命周期、已用时、历史区间和“估算/不可用”。
6. ChatGPT 网页任务保存 session、attempt 和输入 fingerprint，支持等待外部结果、选择结果和同 attempt 重绑。
7. 凭据过期只阻断新任务；已运行任务保持原 runtime owner，恢复后按能力继续或重试。
8. 任务抽屉按进行中、需要处理、历史分组，并可由稳定 task id 精确定位。

### PROJECT-CREATE-001～004｜新建项目

### QUICK-001～005｜自由创作
