## 1. 使用规则

1. 本文是“决策与理由台账”，不是新的架构母稿，也不是版本迭代记录；产品实现与验收仍以架构母稿、交互流程合同、状态真值表、UI 规格和 E2E 矩阵为准。
2. 每个结论使用稳定决策编号。后续修改不得悄悄覆盖旧结论；发生变化时保留原记录，标记为“已取代”，并填写替代决策编号。
3. 决策状态只有：`提议中`、`已确认`、`已取代`。只有用户明确采用的结论可以标记为`已确认`。
4. 每项记录结论、理由、影响范围、原型状态和产品代码状态。原型实现不等于产品代码已实现。
5. 每完成一个页面或流程的讨论，应在同一批修改中更新本文及对应权威规格；若两者不一致，以最新明确确认的决策为线索，先修正文档矛盾再开发。

### BIBLE-002｜项目设定与生成 Prompt 的边界

- **状态**：已确认
- **结论**：项目设定是外部 AI 创作上下文与项目级生产设定的聚合入口，不是图片/视频的通用 Prompt 来源，也不是生图或生视频的强制 Gate。生成链不得把世界观、人物背景/关系或跨集剧情备注整段拼入 Provider Prompt。
- **直接生成输入**：只有 Project Look，以及已经归一化并明确选入当前任务的人物当前外观/生产状态、场景当前生产状态和道具当前生产状态可以参与生成；当前分镜、参考资产、生成模式和 Provider 参数仍由各制作阶段提供，不属于项目设定的通用输出。

### STORY-CUT-001｜分镜与短片职责重划

- **状态**：已确认
- **结论**：分镜阶段承担“镜头设计 → 分镜图/参考图 → Prompt 编译与预检 → 正式逐镜视频生成 → 候选比较与使用”；短片阶段承担“整集镜头审核 → 时间线 → 声音/字幕/后期 → Picture Lock → 交付”。短片保留重新生成、补充候选和局部重拍，但它们是审核修复动作。两阶段必须读写同一 VideoCandidate、adopted pointer、任务和来源快照，不建立第二套候选。
- **理由**：这更符合用户的自然心智，也与 RunningHub 已观察到的“分镜页逐镜生成、短片页整集复核与合片”流程一致；可以避免用户先完成镜头设计，却必须跳到另一个页面重复理解 Recipe/Prompt 才能首次生成视频。
- **交互约束**：生成成功只创建候选；用户显式点击后才采用。改选 adopted 候选不得静默替换已存在的 Timeline clip，必须选择“替换当前时间线片段”或“仅改默认候选”。`进入短片审核` 只是导航，Picture Lock 仍由 Video Gate 硬门禁。
- **原型状态**：统一原型已实现分镜三栏工作台、单镜/批量生成入口、费用确认、候选/历史/采用、异常恢复，以及短片的镜头审核、时间线、后期和交付标签。
- **产品代码状态**：未开发；不得把原型通过解释为 API、SQLite、Provider 或真实媒体链路已经完成。

- **入口与卡片**：头部只有“添加到资产库”，再选择“从本地文件添加 / 从现有项目保存”；卡片预览优先，展示名称、类型、可用状态、版本和使用数量，路径、hash、完整许可与 Provider URI 下沉详情。
- **筛选与状态**：类型、在线状态、来源和排序产生真实结果，支持数量、条件标签、清除条件、搜索空态和筛选空态；离线状态必须落到具体对象，保留元数据和使用位置，禁止用于新项目并提供重新定位。
- **详情与使用**：详情抽屉展示预览、基本资料、版本历史、来源许可、使用位置和文件状态。用于项目必须先选目标项目，再选择“使用这个版本”（默认，固定版本不随库更新漂移）或“复制到项目”（独立副本并保留来源记录），提交后给出可打开目标项目的结果。
- **导入与项目保存**：本地导入执行文件名/类型→预览校验→名称/许可→导入结果；项目保存只保存选中的当前版本，不带入候选、任务或剧集私有信息。重复 hash 必须展示双方版本并选择使用已有、保存为新版本或创建独立资产；支持导入失败、部分成功和安全重试。
- **归档保护**：被项目引用的资产只能归档，不能物理删除；归档后历史引用继续可读，可从已归档筛选恢复。页面/场景切换自动关闭旧详情抽屉，避免对象错绑。
- **落实状态**：统一原型、模型、交互事件、异常场景和自动测试已同步；产品代码未开发。

### QUICK-001～005｜自由创作

自由创作作为 V2.1 可选便捷旁路保留，不是四阶段 Gate，也不恢复旧 FreeCreate 的独立数据链。图片/视频 Recipe 必须先打开配置 Drawer，经过 Provider 能力、引用、费用和耗时预检，再复用统一 Provider、Generation Job、媒体和候选模型提交；视频 H3 编辑默认折叠。关闭页面不停止已提交任务；取消保留 `cancel_requested / unknown` 语义。成功先进入“尚未归档”并提供真实预览、任务/Attempt 与实际费用，结果必须选择下载、加入个人库、绑定项目资产、指定分镜候选或指定短片时间线，或明确放弃；项目/剧集/镜头目标不得使用默认值。首发不做批量生成，所有失败重试创建新 attempt 并保留原任务。

### COVERAGE-001｜52/52 收口

52 个迁移矩阵能力编号全部进入单一覆盖索引，且只映射到 18 个已注册页面；每项均有稳定 feature id、可导航入口和可查看状态。高风险流程提供完整交互，普通功能至少提供入口、前置、正常/异常状态、恢复动作和成功落点。78 个 E2E 保持独立验收语义，纯后端、迁移和并发规则不伪造成独立 UI 页面。覆盖检查只证明规格与原型，不证明产品代码已开发。

## 10. 2026-09-10 短片页重设计（CUT-002）
