# Production Studio V2.1 个人创作者体验收敛与 ChatGPT Web 提级设计

日期：2026-09-09
状态：已确认，统一原型已同步；产品代码未开发
适用范围：V2.1 产品导航、四阶段默认 UI、功能优先级、ChatGPT 网页自动化、任务中心和验收口径
前置决定：保留 V2.1 复杂领域模型；采用个人创作者渐进展开方案 A；ChatGPT Web 可设置为默认生图通道

## 1. 目标

V2.1 的技术模型继续保证结果、任务、引用和版本不会失控，但默认产品界面只要求个人创作者理解“下一步要做什么、哪些内容需要处理、当前使用哪个结果、能否继续”。内部 Revision、Gate、fingerprint、runtime owner、journal 等概念仅在解释问题或高级排查时出现。

唯一 Product Core 成功标准是：个人用户能从项目和剧本开始，完成素材准备、分镜图片、逐镜视频、选片、合片、声音/字幕与 MP4 导出；关闭页面、任务失败、媒体离线或改选候选后仍可恢复。

## 2. 对外部评审建议的取舍

### 2.1 采用

- 保留复杂领域模型，默认 UI 隐藏工程和团队制片术语。
- 技术安全与用户成片闭环分开验收。
- 项目资产与本集设定不形成两套编辑器。
- 六类来源保留，但首屏只展示三个高频开始方式。
- Picture Lock 由“开始合片”自然触发。
- 外部 AI 协作不占项目设置页唯一主操作。
- 超分始终可选，不阻断基础成片导出。
- Quick Create 不进入默认 Rail；高级画布只从阶段内高级入口进入。
- 完整 2D、完整 3D、视频重绘继续排除。
- 新建项目和新建剧集的来源卡必须进入各自真实后续流程，不能用同一个成功占位状态代替。
- 导入资产冲突必须让用户明确选择复用、新建，或仅在引用可缺省时跳过；不能点击“选择处理”后隐式改成新建。
- 已导出、失败回退等终态必须与超分、编码校验和导出 Gate 保持一致，不能同时展示互相矛盾的状态。

### 2.2 调整后采用

- ChatGPT 网页自动化不归 Advanced 或 Non-essential，而是 **Product Core 一级可选生图通道**。
- ChatGPT Web 可以成为全局或项目默认通道；环境不可用时不得静默改写用户默认值。
- 个人资产库保留在全局导航，但首集闭环不强依赖跨项目发布和复杂许可工作流。
- 个人资产库按 `IMPORTANT / P1` 实现：首版只承载人物、场景、道具和音色的跨项目复用。若保留入口，页面内部必须完成预览优先卡片、真实搜索/筛选、详情、用于项目、本地导入、项目保存、冲突、离线和归档闭环；不建设商城、复杂分页或全量媒体管理器。
- 项目完整性与物理清理属于 Platform P0，但只在异常入口和高级数据工具中出现。

### 2.3 不采用

- 不建立 Legacy/VNext 正式并存、`/api/v1` 与 `/api/v2` 长期 Adapter、运行期 feature flag、双写、旧路由回退或发布窗口共存。
- Phase 1～5 继续只做内部开发和验证；Phase 6 按已确认方案冻结任务、备份、写 journal、事务迁移、对账、切换路由并删除旧实现。
- Provider Adapter、外部 AI 适配器和导入格式适配器是稳定领域边界，不等同于 V1/V2 兼容层。

## 3. 产品优先级双轴

| 级别 | 完成定义 | 代表能力 |
|---|---|---|
| Platform P0 | 数据、任务、迁移和 Provider 不丢、不重、不串、不误判 | 幂等、Job/Attempt、Candidate 历史、精确快照、hash、迁移 journal、备份恢复、Provider capability |
| Product Core | 个人用户可以舒适完成并导出一集 | 项目/剧集、剧本、本集素材、资产生图、分镜图、镜头视频、选片、基础时间线、声音字幕、合片、MP4、ChatGPT/API/ComfyUI 生图通道 |
| Product Important | 提升效率、质量、复用和可控性，但不阻塞首集 | 外部 AI 完整协作、批量、人物多状态、音色、Look 版本、H3 高级编辑、连续性、局部重拍、超分、成片历史、个人库高级能力 |
| Advanced | 专业用户按需展开 | 高级画布、完整技术详情、高级 Director 编排、复杂调度；完整 2D/3D/重绘仍不在 V2.1 |

“Platform P0 通过”不能对外宣称核心版本完成；只有 Product Core 端到端旅程通过才可宣称个人版核心完成。

## 4. 导航与页面命名

### 4.1 全局导航

默认 Rail 固定为：

1. 项目；
2. 资产库；
3. 任务；
4. 设置。

Quick Create 改为“更多工具 → 自由创作”，不占默认 Rail。高级画布不设全局入口，只从项目素材、本集素材或分镜的“高级模式”进入并恢复上下文。原型专用 52 覆盖与场景切换器只存在评审构建。

### 4.2 项目内导航

固定为：概览、剧集、项目素材、项目设置。原“项目资产”面向用户改名为“项目素材”；原“项目设定/项目圣经”改名为“项目设置”。内部 route id 可暂时保持稳定，不作为用户术语。

### 4.3 单集四阶段

固定为：剧本、本集素材、分镜、成片。原“设定”改为“本集素材”，原“短片”改为“成片”。不新增第五阶段。

### 4.4 项目列表

项目列表的默认任务是查找项目、识别少量问题并一次点击恢复工作。项目卡显示项目名、封面来源、集数、更新时间、上次工作、当前阶段进度，以及非零的生成中、待处理和需要更新摘要；不显示四组单位不同的阶段统计。整卡进入概览，唯一主 CTA 为“继续第 N 集 · 阶段”。

搜索只承诺项目名，搜索、状态筛选和排序写入 URL。状态固定为全部、制作中、需要处理、已完成、已归档；列表模式必须明显比卡片紧凑。Empty 同时提供新建和导入项目备份；任务暂停必须定位项目任务；索引读取失败提供重试、只读重建索引和高级数据工具。正常本地状态弱化，异常时再提升提示。

### 4.5 项目概览

项目概览只回答“上次保存在哪里、什么会阻止当前工作、项目各阶段整体如何、当前画面风格是什么”。Hero 使用紧凑摘要；“下一步”和“待处理”首屏并列，项目阶段概览与项目画面风格顺次下沉。四阶段统计统一以“集”为单位，不混入素材项或镜头数。

最近成功保存位置用独立 `ResumePosition` 持久化，可按阶段恢复剧集、场次、镜头、工作区标签、检查区、时间位置和候选焦点。当前推荐动作与恢复位置分离：只有直接阻断该位置的硬问题才能把主动作改成“先处理问题”，其他剧集或其他对象的问题只说明影响范围。用户层使用“当前风格版本 / 查看风格”，不显示 Look、Gate 或 ResumePosition 等内部术语。

项目操作首层使用轻量 Popover；导出与恢复再进入 Drawer，删除表达为可恢复的“移入回收站”，高级数据工具跳转独立页。空项目、加载、加载失败、存储离线、需要处理、全部完成和项目不存在都有独立状态；存储离线时只读查看，禁止生成、保存和恢复。

### 4.6 项目剧集

剧集页采用紧凑项目头和行式列表。顶部只显示全部、制作中、需要处理和已完成；日常第一层筛选是需要处理、制作中、已完成、空白和已归档，阶段筛选作为第二层承接概览深链。默认集号升序，最近工作读取真实时间；空项目与筛选无结果分开表达。

四阶段始终可扫描，但未解锁阶段置灰并说明前置条件，有阻塞阶段进入准确问题。继续按钮优先处理硬阻塞，否则恢复到场次、分镜、Inspector、候选或时间线位置。所有创建来源在展开内容和创建任务前先选择“创建下一集”或一个空白剧集；非空剧集永不进入可写目标，严禁默认写入 E01。

外部 AI 等待记录和多集文本生成任务进入全局任务中心。技术上保留 locator、Gate、package、digest 和精确版本，默认页面只展示“继续分镜 03、未解锁、等待外部结果、复用某素材版本”等完成决策所需语言。

### 4.7 项目归档导入

项目归档是低频但核心的本地可靠性能力，保持独立 Page，不混入新建项目来源。个人用户只感知“选择归档、检查并确认、导入结果”三个阶段；Manifest、Schema、Hash、事务编号和内部对象数量默认折叠。页面只允许从当前协议归档创建新项目，不提供覆盖已有项目或猜测升级旧 ZIP。

确认阶段只要求用户判断项目内容、最终名称、保存位置、媒体处理和空间是否可接受。缺失媒体显示为可继续的警告，导入后可重定位；长任务可离页并进入全局任务中心。成功后直接打开项目，历史任务仅作为记录保留，不自动重新运行。

## 6. 创建来源分组

六类来源和安全语义保持不变，入口改为分组展示。

首屏三个入口：

1. **我有剧本**：覆盖手工粘贴、文件导入和已有剧本草稿；
2. **让 AI 帮我写**：从故事想法或初稿生成可审阅草稿；
3. **我有制作包**：覆盖 External AI Result 和 Episode Package，进入同一五步安全预览。

“更多开始方式”展开：

- 空白创建；
- 小说/长文本拆集；
- 已有视频。

外部 AI 完整协作从制作包向导内的次级动作“创建外部 AI 协作任务”进入，不新增主卡。来源卡只改变选中态；用户点击随来源变化的创建主动作后，系统才校验并原子建立项目。新项目来源固定创建第 1 集；已有项目仍可创建新剧集或填充允许的空白剧集。分组只改变信息层级，不合并格式，不削弱目标保护。

### 6.1 剧本阶段个人版投影

剧本页保持“场次—正文—版本与影响”三栏，但默认心智只保留“写、保存、检查并确认”。保存状态必须唯一可信，不显示自动保存毫秒数；恢复副本只在真实存在差异时出现。空剧本没有伪造场次或正文，保存失败、离线和冲突均不能确认。

AI 续写与选段改写统一生成候选，先比较、后应用，不直接覆盖草稿；多集生成和项目复制进入次级选项。版本历史使用“当前草稿、已确认版本、外部 AI 导入”等用户名称，内部 revision id 隐藏；恢复历史只创建新草稿。确认前集中展示预计素材变化和具体下游数量，确认后只写新版本与“需要评估”，既有图片、视频不自动删除或重生成。主操作随状态切换为“检查并确认、确认新版本、进入本集素材、重试保存或解决版本冲突”。

## 7. 项目素材与本集素材

项目素材维护跨集可复用的人物、场景、道具、图片/音色候选和当前使用项。

项目素材默认首屏只展示人物、场景、道具、需要处理四项统计，搜索、类型、简化状态和排序；来源、媒体、使用情况和剧集筛选收入“更多筛选”。默认卡片视图，已确认的紧凑列表入口下沉到更多区域。卡片只承担扫描；整卡打开详情，低频操作进入 `•••`。批量操作必须先进入多选并由用户真实选择范围。

资料修订、媒体候选与当前图指针是三类独立事实。用户点击候选即设为当前图并可撤销；只影响以后选择，已确认剧集的不可变素材快照不自动变化。所有生图通道共用 Generation Envelope 和异步任务语义：提交前统一展示对象、模式、通道、画面风格、参考用途、Prompt、输出、任务、费用与能力检查，提交后先排队，成功才追加候选。

人物默认单图，三/四视图按需展开；场景和道具默认只展开当前剧情状态与主视图。独立俯视图和全景图因被分镜参考绑定、H3 引用编译及走位/连续性检查消费而保留为高级模式，不占默认第一层。从音视频提取人物音色前必须确认来源、许可和用途。

本集素材默认自动继承项目当前使用项，只展示：

- 本集新增对象；
- 与项目默认不同的状态或版本；
- 缺失媒体；
- 当前音频策略要求但缺失的音色；
- 已失效引用；
- 进入分镜前必须处理的少数问题。

用户不需要在本集重新确认所有已继承项。唯一主操作使用“进入分镜”，后台自动执行检查并保存不可变 Asset Snapshot；不再增加“检查并进入分镜”“确认本集素材”等用户可见审批口径。图片差异在本页并排比较后只修改本集选择，条件音色也在本页完成试听、选用或改用模型默认声音。首次准备由实际快照/素材状态决定并展开本集全部所需素材，日常状态只展示例外、缺失或版本变化。本集素材不得复制项目素材的资料编辑、生成参数、参考图、候选历史和删除操作。

外部制作包进入本集素材时必须展示“外部包候选 / 项目当前图 / 本集选择”三方映射；引用不匹配不得猜测。“准备缺失素材”只提交真实缺失项，提交前展示通道、模型、参考、任务数、费用和预计耗时，生成结果仍为候选。自动检查失败和快照保存失败必须分开恢复，媒体离线提供重定位或改选；手工重新检查只作为失败恢复动作出现。

### 7.4 分镜页个人创作者收敛

分镜页保留三栏专业工作台，但默认只服务“逐镜完成”主任务：左侧按需切换镜头描述、引用素材、时间段和连续性；中间在分镜图/视频之间切换主预览和候选；右侧在镜头设计、生成和历史之间切换。场次、镜头和底部轨道必须切换同一真实状态，标题持续显示当前镜头、已采用、待生成和失败数量。

普通生成页不暴露 Recipe、Reference Manifest、revision、fingerprint、AV contract 或完整 H3 JSON。H3 仍是 Product Core 视频生成能力，但其草稿、来源、校验和技术详情进入“高级设置”。站位图、动作预演和高级画布进入辅助视图，不与分镜图同级竞争。

中央视频候选必须先载入主播放器才能采用；不强制用户完整播放。改选当前分镜图后，旧视频保留但标记为基于旧图并退出完成计数。正式任务前统一检查引用、Provider、Prompt/H3 和重复任务，生成中禁用重复提交。`进入成片审核（x/y）` 允许提前审片，但不放松开始合片的镜头完整性门禁。

## 8. ChatGPT 网页自动化通道

### 8.1 产品定位

ChatGPT Web 与 API、ComfyUI 同属 Product Core 一级生图通道，适用于人物状态、场景、道具和分镜图片。它不是唯一通道，也不是 Product Core Gate；缺少 ChatGPT 环境时，用户仍可用其他通道完成成片。

### 8.2 默认通道解析

默认通道按以下优先级解析：

1. 本次生成显式选择；
2. 项目默认生图通道；
3. 全局默认生图通道；
4. 未设置时使用安装时的安全默认值。

用户可以把 ChatGPT Web 设置为全局默认，也可以仅为某个项目设为默认。页面主按钮显示“使用 ChatGPT 生成”；拆分菜单可临时选择 API 或 ComfyUI。单次选择默认不修改项目或全局设置，只有“设为项目默认/设为全局默认”显式动作才持久化。

任务创建时冻结 `resolved_channel`、输入快照和 runtime owner。之后修改默认通道不得迁移、重发或改变已有任务。

### 8.3 环境检测

复用原项目已有的后端与浏览器 Bridge 联合检测，并在以下时机执行：

- 设置 ChatGPT Web 为默认通道时；
- 首次进入需要生图的项目页面时使用短缓存检测；
- 正式发送每个 attempt 前强制刷新检测；
- 用户点击“重新检测”时。

检查项至少包括：

1. ChatGPT Web 通道是否启用；
2. 浏览器可执行文件与 Profile 是否可访问；
3. AIStory/工作台 Bridge 是否可通信；
4. ChatGPT 页面与登录态是否可用；
5. 当前任务是否具备打开/复用会话能力；
6. 结果捕获和回填通道是否可用。

结果分为：

- **可用**：允许排队与发送；
- **需要处理**：提供启动浏览器、打开登录页、重新连接扩展、重新检测等唯一恢复动作；
- **本次不可用**：保留 ChatGPT 默认值，提供“本次改用 API/ComfyUI”，不得静默修改持久化默认。

环境检测不得提交生成内容，不产生生成费用。

### 8.4 任务、队列与结果

- 所有 ChatGPT 任务进入统一 Generation Job/Attempt，不建立页面私有队列。
- 支持关闭抽屉后继续排队、自动发送、等待网页结果、捕获候选、超时后恢复捕获、会话重绑和重复回填去重。
- 无可信 Provider 进度时不显示百分比，只显示“排队中、正在发送、等待网页结果、需要处理”、已用时和历史耗时区间。
- 登录过期、浏览器关闭或 Bridge 失联不会把结果直接判为生成失败；任务进入“需要处理”，保留 attempt 和输入。
- V2.1 中所有网页结果先进入候选。不得沿用旧自动选择第一张并覆盖 current 的行为；批量选择属于用户显式批量动作。
- 若用户选择本次改用其他通道，应创建新的 attempt 并保留原 attempt 记录，不能篡改原执行通道。

## 9. 任务中心

原项目任务能力保留并统一为全局“任务”页面，同时提供项目过滤视图。

### 9.1 全局任务页

默认分为：进行中、需要处理、已完成。支持按项目、剧集、类型和通道筛选。任务行只显示用户决策所需信息：对象、通道、状态、已用时、唯一主动作；输入快照、attempt、fingerprint、原始 Provider 状态和错误栈进入技术详情。

### 9.2 项目内任务入口

项目概览只显示本项目正在运行与需要处理的数量及最多 3 条 blocker。点击进入全局任务页并自动带项目/任务过滤，不另建第二套项目任务中心。人物、场景、道具和分镜的任务入口精确定位到同一 task id。

### 9.3 动作规则

暂停、恢复、取消、重试、重新发送、恢复捕获和重绑只在对应 Provider capability 与任务状态允许时出现。在途任务保持原 runtime owner 收尾；切换默认通道不改变在途任务。

## 10. 项目设置与外部 AI

项目设置从上到下固定为“项目资料与项目画面风格、生产对象概览、外部 AI 创作”。页面 Header 不设置统一保存或外部 AI 主按钮。项目资料独立维护名称、封面、画幅、题材、默认单集时长和输出偏好；本地位置只读。创作上下文独立维护故事基础设定、不可改变的设定和跨集连续性备注，不与项目资料共用表单或 Dirty 状态。

项目画面风格提供预设/自定义基础选择、搜索、影响预览和创建新版本；变更不会自动重新生成历史媒体。生产对象摘要只显示人物、场景、道具数量与最高优先问题，精确进入项目素材分类，不复制候选、版本或生成任务。

“外部 AI 创作”卡提供“编辑创作上下文、复制创作上下文、创建外部 AI 制作任务”三个不同动作。复制只打开预览并支持 Markdown 下载；制作任务复用剧集中心的统一来源与安全目标选择。资料变化时旧上下文显示“需要更新”，复制/任务包失败保留内容并给出恢复动作。

项目资料和上下文表单分别覆盖 Idle、Dirty、Saving、失败保稿、未保存离开、离线只读与草稿恢复。继续编辑必须恢复表单值、未保存提示和保存能力。

外部 V2.1 制作包安全导入属于 Product Core；完整外部 AI 上下文、任务包、相邻集上下文和回流审计属于 Product Important。两者共用确定性导入和目标保护，但不强迫不使用外部 AI 的用户经过协作流程。

## 11. 成片与隐式 Picture Lock

单集“成片”页默认流程为：选择镜头 → 调整顺序/入出点/简单转场 → 字幕与声音 → 开始合片 → 可选超分 → 导出。

用户点击“开始合片”后执行继续前检查。通过时提示：“开始后将固定当前剪辑；之后修改镜头会产生新版本。”用户确认后，内部创建 Picture Lock、Timeline Revision 和基础合片母版。默认 UI 不要求用户先理解 Picture Lock 或审批层级。

超分始终是可选质量增强。跳过、成功或失败回退继续记录在 Post Revision；任何情况下只要基础合片与编码校验通过，用户都能导出基础 MP4。

## 12. Quick Create 与高级画布

两项能力保留在 V2.1 范围，但不进入默认 Rail，不参与首集 Product Core 完成判断。

- 自由创作从“更多工具”进入，继续复用统一任务、媒体和候选；
- 自由创作首发只保留图片/视频两个 Recipe；点击后先配置、预检并确认费用/耗时，再创建可恢复任务；成功结果先进入“尚未归档”，必须选择下载、个人资产库、项目资产、指定分镜候选或指定时间线，或明确放弃；首发不做批量生成；
- 高级画布从项目素材、本集素材或分镜的“高级模式”进入；
- 标准页与画布写同一 command API；
- 原型覆盖导航仍可访问两页，以证明保留能力，但生产导航默认隐藏；
- 完整 2D、完整 3D 和视频重绘继续排除。

## 13. 原型改造要求

统一原型需要同步展示：

1. Rail 收敛为项目、资产库、任务、设置；
2. 项目与单集导航采用新用户名称；
3. 三个高频来源和“更多开始方式”；
4. 项目设置中的外部 AI 卡内动作；
5. 本集素材只显示继承例外、缺失和需要处理项；
6. ChatGPT Web 可设为全局/项目默认，主按钮随解析结果变化；
7. ChatGPT 环境检测的可用、需要处理、不可用与临时改用其他通道；
8. 全局任务页和项目过滤入口；
9. “开始合片”触发固定剪辑说明，技术详情仍可查看 Picture Lock lineage；
10. Quick Create 与 Canvas 从 Rail 消失，但覆盖导航和对应高级入口仍可到达。

原型继续区分 `prototype complete` 与 `product code not developed`。现有产品代码只作为迁移输入和可复用能力证据，不因原型更新而宣称 V2.1 已实现。

## 14. 验收要求

### 14.1 Product Core 旅程

1. 用户把 ChatGPT Web 设为全局默认，新项目继承并以 ChatGPT 作为生图主按钮；
2. 项目覆盖为 ComfyUI 后只影响新任务，旧 ChatGPT attempt 继续原通道；
3. ChatGPT 环境正常时，人物/场景/道具/分镜图片可排队、发送、捕获为候选并显式设为当前使用；
4. 登录失效时任务进入需要处理，重新登录并恢复同一 attempt，不重复发送；
5. 环境不可用时用户可仅本次改用 API，项目默认仍是 ChatGPT；
6. 项目概览任务摘要进入全局任务页并保持 project/task 过滤；
7. 默认本集素材只显示例外和 blocker，继承项无需逐项再次确认；
8. 用户点击开始合片后固定当前剪辑，基础合片成功即可跳过超分导出 MP4。

### 14.2 Platform P0

- 默认解析、任务快照和 runtime owner 不漂移；
- 环境检测零生成费用；
- prepare/send/acknowledge/recover/rebind 幂等；
- 重复回填不创建重复候选；
- ChatGPT 结果不自动覆盖 current；
- 网页任务无假百分比；
- 迁移后不再写旧默认通道字段或旧任务状态；
- Phase 6 失败可按 journal 和备份恢复，不依赖运行期旧页面回退。

## 15. 明确不做

- 不把 ChatGPT Web 设为所有安装的强制默认；
- 不在环境不可用时静默切换并保存 API/ComfyUI 默认；
- 不让网页任务绕过 Candidate、输入快照和任务中心；
- 不恢复 V1/V2 正式双轨、旧路由或旧 API 兼容层；
- 不把 Quick Create、Canvas、完整 2D/3D、视频重绘加入默认个人创作路径；
- 不把任务 attempt、fingerprint、hash、journal 和原始状态放在默认首屏。
