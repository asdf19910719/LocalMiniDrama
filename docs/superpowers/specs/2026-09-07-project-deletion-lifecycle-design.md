# 项目删除生命周期设计

## 背景与问题

当前“删除项目”只更新 `dramas.deleted_at`，项目下的剧集、分镜、制作资产、生成记录、任务和本地文件不会一起删除。界面同时宣称“此操作不可恢复”，导致用户既无法恢复，又无法释放数据和磁盘空间。重新创建同名项目会获得新的数据库 ID 和空数据，但制作页在异步加载前仍可能使用 Pinia 中旧的 `currentEpisode`，从而请求已删除剧集并显示“剧集不存在”。

项目详情页还把“素材库”和“本剧制作资源”放在同一区域：素材库条目可以删除，制作角色、场景、道具却只有编辑按钮。后端虽然存在制作资产删除接口，但只软删除单行，不清理剧集、分镜关联。

## 目标

1. “删除项目”永久删除该项目拥有的数据库数据和专属存储目录，行为与不可恢复提示一致。
2. 删除不影响全局 AI 配置、公共素材库以及其他项目。
3. 新建空项目不进入依赖剧集的制作页，不再短暂请求旧剧集。
4. 项目详情页可以删除本剧制作角色、场景和道具。
5. 单集删除和资产删除使用明确、独立的接口并清理关联关系。
6. 已经产生的软删除孤儿可先预览，再显式清理；工具不得默认执行破坏性操作。

## 非目标

- 不实现回收站、恢复、保留天数和后台定时清理。
- 不按项目名称复用或恢复旧项目；项目 ID 始终是唯一身份。
- 不自动执行历史数据清理。
- 不删除 `drama_id IS NULL` 的公共素材或全局配置。

## 删除语义

### 项目

`DELETE /api/v1/dramas/:id` 变为永久删除。服务先读取项目与依赖 ID，计算删除摘要和项目专属目录；再在一个 SQLite 事务中按叶子到根节点的顺序删除关联表、生成记录、项目素材、剧集和项目。事务提交后，只允许删除位于配置存储根目录下、名称与该项目稳定目录完全匹配的目录。

如果目录不存在，数据库删除仍视为成功。如果目录删除失败，接口返回数据库已删除但文件清理失败的明确错误和目录信息，并记录日志；不得回滚出一个数据库已恢复、文件却部分删除的状态。

删除响应包含按表统计的删除行数、文件目录、文件数量、释放字节数和文件清理状态，供界面展示结果。

### 剧集

新增 `DELETE /api/v1/episodes/:id`。只能删除所属项目仍存在的剧集。事务中删除该集的分镜关联、提示词草稿、分镜图片/视频记录、合成与超分记录、集内场景和道具、剧集角色关联、导入溯源和剧集本身。项目级角色、场景和道具不因删除一集而删除；仅解除或删除明确属于该集的数据。

前端不再通过提交“剩余全部剧集列表”间接删除。

### 制作资产

角色、场景、道具删除接口继续保持现有 URL，但改为事务性永久删除业务记录及关联：

- 角色：删除 `episode_characters`、`storyboard_characters`、`storyboard_character_variants` 和角色变体，再删除角色。
- 场景：把引用该场景的 `storyboards.scene_id` 置空，再删除场景。
- 道具：删除 `storyboard_props` 关联，再删除道具。

资产删除不立即删除单个媒体文件。文件仍位于项目专属目录，并在项目永久删除时统一清理，避免误删被生成记录或素材库复用的文件。界面文案说明删除的是项目资源及其关联。

## 数据所有权边界

项目永久删除覆盖：

- `dramas` 及其 `episodes`。
- 剧集分镜、角色/场景/道具关联、帧提示词、H3 草稿。
- 项目制作角色、角色变体、场景、道具。
- `drama_id = 项目 ID` 的项目素材库条目和 assets。
- 图片、视频、合成、超分、统一生成任务与外部生成会话/任务/结果。
- 单集外部 AI 制作包任务和导入溯源。
- 通过上述记录能够确定归属的异步任务和导演候选数据。
- `storage/projects/<项目稳定目录>`。

明确保留：

- `drama_id IS NULL` 的公共角色、公共场景、公共道具。
- AI 服务配置、模型映射、全局设置、提示词覆盖。
- 其他项目的任何记录和文件。

## 新建项目与前端状态

项目列表创建成功后跳转到 `/drama/:id`。空状态引导用户“新增剧集”或“导入制作包”，不自动创建空白第一集。

进入或切换 `/film/:id` 时，必须在发起任何加载前同步清空旧的 `currentEpisode`、剧本内容、选中剧集和不属于新项目的 `episode` 查询参数。只有新项目详情加载完成并选中有效剧集后，剧集进度组件才允许请求后端。

## 项目详情页

“本剧制作角色/场景/道具”卡片增加危险色删除按钮，复用制作页的业务接口。删除成功后重新加载项目；确认文案包含资源名称和关联会被移除的说明。“素材库”删除入口保持不变，但标签和提示明确它操作的是素材库副本。

## 历史孤儿清理

提供命令行脚本，默认仅输出预览。只有同时传入 `--execute` 和明确的 `--drama-id <id>`，且目标项目已经软删除时才允许调用同一项目永久删除服务。脚本拒绝清理仍有效的项目、无效 ID 和存储根目录之外的路径。

## 错误与安全

- 无效或不存在的项目/剧集/资产返回 404。
- 删除服务使用参数化 SQL 和数据库事务。
- 文件路径必须通过 `path.resolve`、`path.relative` 和真实路径边界校验；禁止删除存储根、`projects` 根或其外部路径。
- API 不按标题查找项目，同名项目互不影响。
- 重复删除返回 404，不产生跨项目副作用。

## 验证

- 服务测试覆盖项目全量删除、跨项目隔离、公共素材保留、目录安全、文件统计和目录不存在。
- 路由测试覆盖删除响应和 404。
- 剧集测试覆盖子数据删除与项目级资产保留。
- 资产测试覆盖角色关联/变体、场景引用置空、道具关联清理。
- 前端测试覆盖新建跳转、切换项目先清状态以及项目详情页删除入口。
- 运行全部后端测试、全部前端测试和前端生产构建。
