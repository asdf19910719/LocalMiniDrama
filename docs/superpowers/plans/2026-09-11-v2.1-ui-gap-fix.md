# V2.1 UI 审计缺口全面修复 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 修复《V2.1 UI 实现 vs 设计/原型文档 逐页逐弹窗遗漏审计》中的全部 P0/P1 问题及可落地的 P2，使 UI 与规格/原型对齐。

**Architecture:** 按审计报告（`docs/vnext/v2.1-ui-vs-design-gap-audit-2026-09-11.md`，为本计划的 traveling spec）的优先级分 6 阶段执行；以文件冲突域划分子任务并行派发；每个任务带测试与独立提交；`frontweb/src/v21/api.js`、`router/index.js` 等中枢文件由主线程统一修改后再并行派发页面级任务。

**Tech Stack:** Vue 3 Options API + Element Plus（前端）、Express + better-sqlite3（后端）、Node 内置 test runner。

**Spec:** `docs/vnext/v2.1-ui-vs-design-gap-audit-2026-09-11.md`（含每条发现的规格/原型与实现双边行号证据）

## Global Constraints

- 纯 JavaScript，无 TypeScript；前端 Element Plus 组件库已引入。
- 后端测试：`cd backend-node && node --test test/*.test.js`；前端测试：`cd frontweb && node --test test/*.test.js`；构建：`cd frontweb && npm run build`。
- 不改变既有通过的后端行为契约（1026 个后端测试为回归底线）；新增端点必须带测试。
- 每个功能性变更批次同步更新 `CHANGELOG.md`（[未发布] 章节，按新增/优化/修复分类）。
- 遵循审计报告 §3 已按决策裁剪的核对项——不得复活被决策移除的功能（多轨时间线、平级声音资产、总览 Tab 等）。
- 用户语言文案：使用"需要处理"而非"阻塞"、"人物"而非"角色"（规格 §15/§24 口径）。
