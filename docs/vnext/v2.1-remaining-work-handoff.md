## 1. A 类：执行器级缺口（最高优先级）

### A1. 真实 Provider 接入（价值最高）

**现状**：V2.1 分镜图（`storyboardService.generateImage`）、镜头视频（`submitVideo`→`mockProvider`）、H3 编译（`compileH3Text` 确定性文本）、自由创作（`/api/v2/quick-create/*`）全部走 `mockProvider` 确定性通道。真实能力在旧后端已存在但未接入 V2.1 新链路。

**目标**：配置了真实 Key 时走真实 Provider；无 Key 自动回落 mock（铁律 6）。UI 不需要改（生成 Sheet 已展示通道/费用占位，需改为真实返回值）。

**做法**（建议）：
1. 在 `backend-node/src/v21/` 新建 `providerRouter.js`：读取 `ai_service_configs`（经 `aiConfigService`）判断可用通道；提供 `resolveImageChannel(projectId)` / `resolveVideoChannel(shotId)`，解析顺序＝本次覆盖→项目默认→全局默认→安装默认（见交互规格 §13.3）。
2. 图片：接 `imageGenerationOrchestrator`（`src/services/imageGenerationOrchestrator.js`，已支持 API/ChatGPT 网页/ComfyUI 三通道与任务队列）；产出仍写 `image_generations`（候选语义不变）。
3. 视频：接 `unifiedVideoGenerationService`（`src/services/unifiedVideoGenerationService.js`，MiniMax H3 等）与 `videoProviders/`；H3 编译接 `h3PromptDraftService.compileDraft`（真实 H3 结构），把结果写回 `storyboard_h3_prompt_drafts`；候选仍写 director 三表。
4. Provider capability（时长/引用数/分辨率上限）接 `videoCapabilitiesService` / `modelCapabilityValidator`，驱动分镜页联合检查第 2 行与生成 Sheet 的规格行（当前 mock 恒通过）。
5. 费用：真实 Provider 返回价或"Provider 未返回价格"，替换生成 Sheet 中硬编码 ¥0。

**验收**：配置一个真实 Key 后，分镜图/视频产出真实媒体且仍走候选→采用合同；不配置 Key 时 mock 全流程不变；`test/v21StoryboardVideo.test.js`、`test/v21Integration.e2e.test.js` 保持全绿（新增真实通道测试用 fake adapter，不发真实请求）。

### A2. 完整性检查扫描器

**现状**：`frontweb/src/views/productionStudio/DataToolsView.vue`（路由 `/settings/data-tools`）结果为硬编码演示数据。
**做法**：后端新建 `backend-node/src/v21/datatools/integrityService.js`，端点 `POST /api/v2/datatools/integrity/run`，逐项执行：
- SQLite：`PRAGMA integrity_check`、`PRAGMA foreign_key_check`
- 媒体存在性：遍历 `image_generations.local_path`、`characters/scenes/props.image_url→local_path`、`director_artifacts.artifact_path`，检查文件存在与大小
- 引用检查：episode_characters→characters、storyboard_character_variants、storyboard_props、storyboards.scene_id 悬空引用
- 任务索引：async_tasks.resource_id/owner_id 指向不存在的资源
- 受控目录越界：路径解析后不在 `data/` 内的记录
- 孤儿文件：storage 下未被任何行引用的文件
每项产出 `{severity: ok|warn|error, item, recovery}`，recovery 映射到前端已有落点（媒体重定位/重建任务索引/物理清理/路径配置）。前端 DataToolsView 把演示数组替换为真实结果并加"正在检查"进度态。

### A3. 物理清理执行器

**现状**：DataToolsView「物理清理」dry-run 清单为演示数据，删除不真实执行。
**做法**：后端新建 `v21/datatools/cleanupService.js`：
- `dryRun()`：扫描 storage 下文件，逐文件判定——引用计数（image_generations/director_artifacts/characters/scenes/props 行引用）、活动任务占用、路径是否在受控根内；输出可清理/阻断+原因
- `execute(items, confirmText)`：校验 confirmText === '永久清理'；真实删除；输出 `{deleted:[], failed:[{path,reason}]}` 并写报告文件到 `data/backups/cleanup-reports/`
前端：dry-run 清单换真实数据，删除按钮真实执行，展示已删除/未删除与报告位置。

### A4. 工作区迁移执行器

**现状**：`ProjectOverviewView`… 实际在 `SettingsView.vue`「更改工作区」Modal（设计稿 24），确认按钮 disabled。
**做法**：后端新建 `v21/datatools/workspaceMigrationService.js`：`migrate(newDir)` 步骤＝活动任务检查（有则拒绝）→ 新目录权限/空间检查 → 备份（复用 `v21/backup/backupService.js`）→ 复制 db+storage → 原子改 `configs/config.yaml` 的 database.path 与 storage.local_path → 写迁移记录。前端解禁按钮，串六步状态（选择→检查→范围预览→执行→重新打开提示）。**执行前必须已有备份**，失败回滚路径配置。

### A5. 媒体重定位扫描器

**做法**：后端 `v21/datatools/relocationService.js`：`scan(dir)` 按 相对路径→文件名→大小→hash 匹配缺失媒体（`local_path` 不可访问的行），输出唯一匹配/多候选/未找到三类预览；`confirm(items)` 才真实 UPDATE 路径。前端 DataToolsView「媒体重定位」按此接：选目录→扫描→逐文件预览（复用设计稿 20 的行样式）→确认更新。

## 2. B 类：向导级缺口（后端 API 多数已就绪）

### B1. 「更新分镜结构」diff 向导（设计稿 10 更多菜单 / STORYBOARD-016）

**现状**：`StoryboardStage.vue` 更多菜单「更新分镜结构（从已确认剧本重建）」直接调 `createFromScript`（追加新行），无 diff 预览、无版本化替换。
**做法**：
1. 后端 `storyboardService` 增加 `previewStructureDiff(episodeId)`：从已确认剧本重新推导结构（复用 `createFromScript` 的推导逻辑但只读），与当前 `storyboards+storyboard_segments` 对比，输出 `{added:[], changed:[{shotId, fields}], removed:[], unchanged:n}`；再增加 `applyStructureDiff(episodeId, diff, {expectedRevision})`：事务内按 diff 增/改/删行（删除仅标记 deleted_at，媒体候选保留并标 stale），递增全部受影响镜头的 structure_revision。
2. 前端：更多菜单该项改为向导（复用 Modal 18 的 imp-row 行样式）：预览 diff → 处理冲突（人工改动镜头默认保留并标"跳过"）→ 确认创建新结构版本。
**验收**：重建不丢人工时段编辑（跳过的镜头不动）；媒体历史不删除；`SHOT_REVISION_CONFLICT` 仍生效。
