# Production Studio V2.1 剩余原型页面·个人创作者视角评审

日期：2026-09-10
范围：除分镜（STORYBOARD-021）与短片（CUT-002）外，统一原型全部 15 个页面。
方法：逐页盘点当前原型实现（布局区 / 工具栏 / 抽屉数 / 场景数 / 可见术语 / 主 CTA），按分镜与短片重设计确立的新标准复审。
性质：评审建议，不含实现；每页给出「保持 / 微调 / 重排 / 重设计」结论与优先级。

## 0. 评审标准（来自 09-09 收敛设计 + STORYBOARD-021 / CUT-002 新基线）

1. **一个页面一个核心闭环**：单屏优先；能用一个主按钮说清页面目的，就不用三个标签。
2. **正交状态维度少**：分镜页从 6 维降到 1 维是标杆；任何页面不应同时让用户管理 3 个以上可切换的视图维度。
3. **技术概念不上页面**：revision、fingerprint、snapshot、hash、manifest、Gate、attempt、canonical、pointer 等词对个人创作者不可见（折叠进"技术详情"或改白话：草稿/已确认/需要更新/候选/当前使用）。
4. **抽屉克制**：低频操作收进「更多」；一个页面的常驻抽屉入口超过 6 个就要问"这些真是同一个任务里的吗"。
5. **费用靠近提交、一切可恢复**；术语用个人创作者语言。
6. **能力分层**：CORE 优先占屏，IMPORTANT 可达，P2 收进高级入口。

## 2. 逐页评审

### 2.1 projects 项目列表 — 保持
现状：单栏卡片流 + 搜索/排序/状态筛选 + 卡片|列表切换；错误场景 1 个抽屉；几乎无技术术语；卡片主按钮"继续 分镜 03"直达续作。
建议：保持。这是全站个人创作者语言的标杆页。P3 可做：状态筛选 5 项（全部/制作中/需要处理/已完成/已归档）与卡片健康 tag 的口径保持与剧集页一致即可。

### 2.2 project-new 新建项目 — 保持
现状：单栏表单（项目信息 + 来源卡 3 主 3 更多）+ 10 场景；抽屉仅保存位置与放弃确认。
建议：保持。来源卡随来源变化主按钮文案（"创建项目并导入剧本"等）是好实践。P3 可做：磁盘空间预估（4.8 GB）措辞保留，但"可写权限/同名目录"检查行可在通过时收起。

### 2.3 project-import 项目归档导入 — 重排（P2）
现状：9 个阶段；导入确认后为双栏（归档内容/导入到哪里）。术语全局最密：`local-mini-drama.project-archive@2.1` 协议 tag、Manifest 类型、Schema、逐文件 Hash、归档版本 v1.4/2.1、事务/回滚、临时解压峰值。
问题：个人创作者导入自己的备份，关心的是三件事——"里面有什么 / 会不会覆盖什么 / 失败了怎么办"。Hash、Schema、协议版本是工程信任语，不是用户信任语。
建议：
1. 主流程保留五步：选择归档 → 检查结果（可读问题清单：缺失媒体 2 个、版本较旧）→ 选择目标（名称/位置/媒体处理）→ 导入进度 → 结果（打开项目 / 重试）。
2. 协议名、Manifest/Schema、逐文件 Hash、归档版本矩阵全部收进"技术详情"折叠；页面层保留"共 N 个剧集 · M 个素材 · 2 个缺失媒体"这类可读计数。
3. "事务/回滚"改为结果语言："导入中断时不会留下半个项目；已自动还原"。
4. "媒体处理"（复制到项目目录/保留原路径引用）保留，但补一行后果说明（"复制更安全但占用 2.1 GB；引用不占空间但移动原文件会失效"）。

### 2.4 project-overview 项目概览 — 保持
现状：四面板（下一步 / 待处理 / 阶段概览 / 画面风格）+ 三类抽屉；恢复位置精确到场次/镜头；术语少。
建议：保持。P3 与 09-10 决策对齐：阶段名"本集素材"→"设定"统一（该改动已在 09-10 在途改造中，注意与测试矛盾一起收口）。

### 2.5 project-bible 项目设置 — 微调（P2）
> 2026-09-10 用户澄清：**外部 AI 协作是核心能力，必须保持在主区且功能完整**；只允许优化交互设计与名称，不允许降级或移入"更多"。下述建议已按此修正。
现状：四面板 + look 子视图；7 个抽屉（资料编辑/上下文编辑/上下文预览/风格选择/影响预览/版本比较/放弃确认）；"外部 AI 协作"占据 wide 主区。
建议（修正后）：
1. **外部 AI 协作保持在主区块位、功能完整性不减**：上下文摘要、缺失字段、恢复动作、复制创作上下文、创建制作任务全部保留。优化方向仅限交互与语言：
   - 面板内按"任务流"重排：①确认给外部 AI 看什么（创作上下文摘要 + 缺失字段补全）→ ②生成与交付（复制上下文 / 创建制作任务）→ ③等待与结果（恢复动作、任务入口）；
   - 名称优化："创作上下文" → "给外部 AI 的项目说明"；"Markdown" → "说明文件（Markdown）"；"任务包" → "制作任务包"。
2. 抽屉收敛（不涉及外部 AI 功能的合并）：资料编辑与创作上下文编辑可合并为一个"编辑项目设定"抽屉（两个分区）；上下文预览并入编辑抽屉的只读态。7 → 5 左右。
3. "风格版本 v4"、"版本记录"进风格面板局部，页面层无 revision 字样。

### 2.6 project-episodes 项目剧集 — 重排（P1）
现状：全局最重——28 场景、11 个抽屉函数；stats 四格 + 双组筛选（状态 6 项/阶段 5 项）+ 排序与管理；外部 AI 协作任务卡在 waiting 态常驻列表上方；tool-note 出现"Gate"。
问题：
1. "阶段入口遵循当前剧集 Gate"——Gate 是全站最该清掉的术语，直接违反 09-09 术语收敛。
2. 外部 AI 协作任务卡常驻首屏，但对大多数时间的大多数用户是不可动作的等待态。
3. 六类来源入口虽然已收敛为 3 主 + 更多，但导入链路仍是"选择目标 → 来源流程 → 五步向导（选择→解析→结构→资产→差异→确认中的五步）"，抽屉套抽屉。
4. 行级信息密度高但可用：编号+标题+来源 pill+四阶段入口格+行动按钮，这部分是好的。
建议：
1. "Gate" → 行动语言：锁定行显示"先确认剧本，再进入分镜"式下一步提示（概述页已有此语言，统一即可）。
2. 外部 AI 协作任务卡（核心能力，功能不减）：按状态分层呈现——等待用户动作时保持横幅常驻并高亮；纯等待外部产出的状态压缩为单行进度条（含任务入口），不展开整卡；已完成态归档进行内审计入口。
3. 导入向导 5 步并为 3 步：选择文件与映射（合并解析/字段映射）→ 预览（结构 + 资产匹配 + 差异同屏）→ 确认写入；抽屉 11 个可收敛到 7~8（审计与菜单保留）。
4. 筛选：状态 6 项保留；阶段筛选 5 项与状态筛选有重叠感，可收进同一行两个下拉（已是），保持。

### 2.7 project-assets 项目素材 — 重排（P1）
现状：列表 + 原地详情（合理）；21 场景（18 横幅）、7 抽屉；筛选体系庞大（类型 tabs + 搜索 + 主筛选 + 更多筛选 + chips 行 + 多选批量条）。
问题：
1. 卡片直接显示"资料 r2/r3"（dataRevision）——个人创作者不管理资料版本号，只关心"这张图是不是最新的、被哪里用了"。
2. 横幅/状态文案露出"快照"、"当前指针"、"通道"、"候选 B 文件损坏（可读性尚可）"。
3. 筛选维度多但都有真实用途（09-09 已收敛过一轮），结构可保留。
建议：
1. 版本语义下沉：卡片层只显示状态（使用中/有新版/缺失参考）；"资料 r2"进详情页的版本记录区。
2. 术语替换："原输入快照"→"生成时的输入记录"；"当前指针"→"当前使用"；"通道"→"生成方式"；"固定引用"→"已固定本集版本"（与分镜页语言一致）。
3. 18 种横幅按用户动作分四类合并：需要处理（缺失/损坏/冲突）/ 有更新可选 / 只读原因 / 流程进行中。
4. 批量操作条与"生成前检查"抽屉保留（费用靠近提交的好实践）。

### 2.8 studio-script 剧本 — 微调（P2）
现状：三栏（场次列表 / 编辑器 / 版本与影响）+ 10 抽屉 + 14 场景；主按钮状态机（检查并确认→保存中→确认新版本→进入本集素材）。
问题：
1. 右栏"版本与影响"常驻三分之一宽度，但"版本历史 / 素材提取差异 / 确认后的具体影响"都是低频信息——个人创作者 90% 的时间只需要左栏 + 编辑器。
2. 术语："基于已确认版本"、"N 处差异"、"人工锁定/删除候选"、"按原范围和输入快照重试"、"下游影响"。
建议：
1. 右栏改为默认折叠的 details（"版本与影响"），展开才占宽；三栏变两栏 + 折叠栏，与短片页"成片设置"右栏同宽体系。
2. 术语替换："下游影响"→"确认后会影响什么"（内容本身已是白话，仅标题）；"输入快照"→"生成记录"；"人工锁定/删除候选"→"保持我的修改 / 建议删除（需确认）"。
3. 确认流程三步（检查 → 素材差异 → 确认）可并为两步：检查与影响同屏 → 确认。AI 候选（先比较后应用）是好实践，保留。
4. 场次列表 + 编辑器双栏是 CORE，保持。

### 2.9 tasks 任务中心 — 微调（P2）
现状：三 tab（进行中/需要处理/历史）+ 4 维筛选 + 搜索；15 种内联状态；任务详情抽屉 1 个（技术详情已折叠）。
问题：列表行级露出 attempt、fingerprint、lifecycle、runtime owner、billingStatus（计费状态）；对个人创作者，行内需要的是"第几次尝试 / 大概还多久 / 花了多少钱"。
建议：行内术语替换——attempt →"第 N 次"；fingerprint/lifecycle/runtime owner → 折叠进任务抽屉的技术详情（现状已有折叠，把行内残留移进去）；billingStatus →"预计 ¥x / 实际 ¥x"。其余保持。

### 2.10 library 个人资产库 — 保持（P3 微调）
现状：09-09 已收敛；12 场景一致；6 抽屉；"用于项目"主 CTA 清晰。
建议：保持。P3：hash/source hash/Provider URI 收进详情抽屉技术区（多数已如此）；归档策略说明保留。

### 2.11 quick-create 自由创作 — 微调（P2）
现状：单屏 4 区（生成方式 / 本次生成设置 / 结果去向 / 生成历史）+ 5 抽屉 + 17 场景；"可选工具·不影响四阶段进度"定位清晰。
问题："Recipe"、"canonical Generation Job"、"输入快照/费用快照"露出；"自由创作实验室"命名偏工具向。
建议：
1. "Recipe" → "生成方式"；"canonical Generation Job" → "任务"（页面层不需要"统一任务模型"的实现语）。
2. "自由创作实验室" → "自由创作"（与入口名一致）。
3. 五类去向、配置→预检→费用确认→提交链路是 CORE，保留。H3 高级草稿折叠保留。

### 2.12 canvas 高级画布 — 保持（P3 修 bug）
现状：定位 P2 高级工具，"标准页面的高级投影，不拥有第二套数据"边界清晰；从分镜"更多"与素材页高级入口进入。
建议：保持。**修一个 bug**：model 的 getCanvasModel scenarios 缺 `selection`/`multi-selection` 两个键（route 注册了 19 个场景，模型只有 17 个，访问会抛 "Unknown canvas scenario"）。另外画布上的共享命令裸 id（useAssetVersion 等）如需展示，改为动词短语。

### 2.13 settings-ai AI 配置 — 保持（P3 微调）
现状：四面板（默认通道/网页环境/业务映射/Provider）+ 8 抽屉 + 21 场景；配置页允许比创作页更高的技术密度。
建议：保持。P3：fingerprint、"输入 fingerprint 不匹配时必须阻断"这类文案改为"检测到配置已变化，运行中任务不受影响，新任务需重新检测"；四层解析顺序解释保留（这是用户真正需要理解的心智模型）。

### 2.14 settings-general 常规设置 — 保持
现状：五面板 + 6 抽屉 + 16 场景；"迁移 journal/物理清理由高级数据工具负责"的引导清晰。
建议：保持。

### 2.15 settings-data 高级数据工具 — 保持
现状：全局抽屉最多（16 函数/24 调用点）、术语最密（dry-run/journal/回滚/事务），但自述"日常创作不会进入这里"，且每类工具（完整性/重定位/迁移/清理）都有 dry-run 前置与确认链。
建议：保持。该页的复杂性与其"故障恢复/高级维护"的目标用户是内聚的；不要为了统一而稀释它的严谨性。

## 3. 横切主题（跨页面统一处理）

1. **全局术语清扫清单**（一次性替换，配合测试）：
   - Gate → "还差 X 步 / 入口未就绪 / 先确认剧本"；
   - Recipe → "生成方式"；
   - canonical (Generation) Job → "任务"；
   - 快照 → "生成时的输入记录"（或折叠）；
   - 指针/当前指针 → "当前使用"；
   - attempt → "第 N 次"；
   - fingerprint → "校验码"（折叠）；
   - 资料 rN（dataRevision）→ 下沉到详情版本记录。
2. **"版本"语言统一**：目前同时存在剧本"已确认版本/草稿"、素材"资料 r2"、风格"v4"、成片"vN"四种表述。统一为对象级"第 N 版 + 时间"，页面层不再出现 revision 字样。
3. **抽屉预算**：创作主页面（studio 四页）常驻抽屉 ≤ 5；项目页面 ≤ 8；设置/数据工具不设限（目标用户不同）。episodes（11）与 bible（7）是唯二超标的创作侧页面。
4. **常驻卡片审计**：episodes 的外部 AI 任务卡、overview 的待处理列表是仅有的两个常驻态卡片；原则——只有"等待用户动作"的才常驻，纯等待态进任务中心。
5. **与在途改造的耦合**：09-10"项目设置一级导航移除 + 本集素材改名设定"的改造（现有 2 个失败测试）应与 P1/P2 页面重排同一批收口，避免测试反复。

## 4. 建议实施顺序

1. **第一批（P1）**：project-episodes 重排、project-assets 术语与版本下沉（两者与在途导航改造同批）。
2. **第二批（P2）**：studio-script 右栏折叠 + 确认流程两步化；project-bible 外部 AI 下沉与抽屉收敛；project-import 技术细节下沉；quick-create / tasks 术语微调。
3. **第三批（P3）**：canvas 场景键 bug 修复；settings-ai 文案微调；全局术语清扫回归测试。
4. 每批沿用分镜/短片的实践：设计文档 → 测试先行 → model → HTML → 文档同步（规格/决策记录/E2E/评审/CHANGELOG）→ 浏览器实测。
