# RunningHub RHSTORY 交互模式

> 本文区分“已观察到”“由截图/多页面交叉确认”“建议性解释”。交互存在不代表其服务端结果或异常分支已经实测。

## 1. 模式总览

| 模式 | 观察结论 | 典型位置 | 对工作流的作用 |
|---|---|---|---|
| Modal | 已确认 | 全局画风、批量生成、导入、添加变装、参数/确认 | 在不离开阶段的前提下完成一次短事务 |
| Drawer | 已确认 | 账户面板、资产详情、历史、AI 会话 | 保留背景上下文，容纳长表单或持续信息 |
| Inspector | 已确认 | 分镜左栏、自由画布节点、资产详情 | 围绕当前选择显示结构和约束 |
| Context Menu | 已确认存在于项目卡/镜头局部操作；完整项未全实测 | 项目更多、镜头插入/删除/合并 | 把低频/危险动作移出主点击区 |
| Inline Editing | 已确认 | 剧本正文、资产名称、项目/单集名称、提示词 | 缩短“查看—编辑—保存”的距离 |
| Drag & Drop | 已确认 | 剧本/分镜/视频上传、2D/3D/节点画布、时间线重排 | 对文件、空间和顺序操作更直接 |
| Selection | 已确认 | 当前阶段、资产类型、资产卡、镜头、候选、画风 | 建立稳定的当前工作上下文 |
| Multi-selection | 已确认 | 批量生成资产、批量下载/批量生成 | 将重复操作提升为批次 |
| Batch Operation | 已确认 | 资产生图、故事板/分镜图/站位图/视频、下载 | 支持真实生产规模 |
| Async Task | 已确认 | 文本生成、提取、生图、生视频、音色、增强、合成 | 承接长耗时和第三方不确定性 |
| Notification | 已确认有消息/会话/状态反馈；各 Toast 文案未全实测 | 顶部消息、对象状态、历史、AI 会话 | 告知结果，并把长任务导向可恢复状态 |

## 2. Modal

### 2.1 已观察类型

- **选择器 Modal**：全局/局部画风，顶部分类和搜索，主体为卡片网格；
- **批处理 Modal**：资产多选、统一参数、总价和提交；
- **导入 Modal**：文件拖拽、格式说明、解析与合并规则；
- **轻量创建 Modal**：添加变装/衍生状态、新建单集；
- **确认 Modal**：删除、重新确认、发布等高影响动作（入口确认，未执行危险最终动作）；
- **媒体预览 Modal**：大图、整集播放或片段处理。

### 2.2 为什么适合

Modal 适合“短、封闭、需要完成或取消”的事务。例如选择画风时，用户仍需要看到背后的设定页，但不需要永久占用一列。打开 Modal 后背景控件被禁用，减少误触。

### 2.3 设计约束

- 打开后焦点进入弹窗，关闭后回到触发按钮；
- 未应用的选择不能静默修改项目；
- 批量生成提交前展示对象数量、跳过规则、Provider、规格和费用；
- Modal 不嵌套超过两层；
- 大型风格库应虚拟滚动、延迟加载并保留筛选状态。

## 3. Drawer

### 3.1 已观察类型

- 账户抽屉：身份/空间、钱包、消耗看板、新手指引、水印和退出；
- 资产详情抽屉：当前图、候选、参考素材、描述、参数、任务与确认；
- 历史记录抽屉：当前镜头或任务的候选历史；
- AI 项目会话抽屉：连接状态、历史会话、上下文提问。

### 3.2 为什么适合

Drawer 适合“长、可滚动、与背景选择持续关联”的内容。资产详情从右侧展开时，用户仍能看到资产卡所在位置；切换卡片后可以复用同一详情面板。

### 3.3 风险

- 账户抽屉与资产详情抽屉同时存在会争夺右侧空间；应规定互斥；
- 移动端或窄屏下应转为全屏页；
- 生成按钮固定底部时，不能遮住错误、价格和参数摘要；
- 关闭前应处理未保存表单，保留滚动位置。

## 4. Inspector

分镜左栏是最典型的 Inspector。它围绕当前镜头聚合：

- 镜号和时长；
- 出镜角色、角色状态、音色；
- 场景、场景变体、道具；
- 故事板、分镜图、站位图；
- 附加图片、视频、音频；
- 2D/3D 预演入口。

Inspector 的价值是把“当前镜头是否具备生成条件”变成可扫描清单。它不承担全项目资产管理，而是展示已绑定资产及其版本、状态和缺失原因。

应支持：列宽拖拽与恢复默认、分组折叠、缺失/过期定位、键盘在相邻镜头间移动。宽度变化不能挤掉中栏价格和生成按钮。

## 5. Context Menu

Context Menu 适合低频、局部或危险动作：

- 项目卡：重命名、删除等；
- 镜头卡：前后插入、删除、合并；
- 候选/媒体：下载、查看任务、删除、设为主结果；
- 画布节点：复制/删除/连接等（部分项需实施前再验证）。

“选择镜头/项目”应占据主点击区；删除不能与选择共享无区分图标。菜单项需要明确对象名称和影响，禁用项要解释原因，例如“合并后 37s，当前模型最大 30s”。

## 6. Inline Editing

### 6.1 典型对象

- 剧本正文大文本编辑；
- 项目名、单集名、资产名轻量编辑；
- 分时码提示词与内联 `@角色/@场景` 芯片；
- 结构化描述和自由画布节点字段。

### 6.2 语义规则

- `dirty`、`saving`、`saved`、`save_failed` 必须可见；
- 轻量名称可回车保存、Esc 取消；
- 剧本和提示词必须显式保存或自动保存并展示版本；
- 编辑已确认内容只产生新草稿，不立即重写下游；
- 重命名资产不能破坏引用，底层引用稳定 ID。

## 7. Drag & Drop

### 7.1 已确认用途

- 拖入剧本、分镜脚本或视频文件；
- 自由模式节点移动和连线；
- 2D 画板放置/绘制，3D 导演台摆放对象与机位；
- 短片/镜头轨重排和裁剪（部分细节由实机与生产前端资源交叉确认）。

### 7.2 为什么适合

文件、空间关系和时间顺序具有天然的直接操纵模型。拖拽让用户在对象本身上表达意图，而不是填写位置数字。

### 7.3 必须补充的非拖拽路径

- 文件选择按钮；
- 上移/下移或排序菜单；
- 数值坐标/时长输入；
- 键盘可操作的选择与移动；
- 拖拽前后清晰的落点、撤销和结果通知。

## 8. Selection

RHSTORY 同时存在多层选择，必须保持语义独立：

| 选择类型 | 视觉反馈 | 状态影响 |
|---|---|---|
| 阶段选择 | 步骤胶囊高亮 | 改变页面/阶段上下文，不等于完成 |
| 资产类型选择 | 标签高亮 + 数量 | 只筛选角色/场景/道具 |
| 当前资产 | 卡片边框/详情抽屉 | 改变 Inspector 内容 |
| 当前镜头 | 镜头轨边框 + 镜号 | 改变左中右三栏上下文 |
| 画风选择 | 卡片选中态 | 应在应用后改变风格绑定 |
| 候选选用 | 主候选标记 | 改变当前采用结果，是业务状态变更 |

不能仅依靠荧光色表达选择，还应配合文字、图标、边框或 `selected` 语义。

## 9. Multi-selection 与 Batch Operation

批量操作的标准流程应是：

```text
进入多选模式
→ 选择范围/筛选条件
→ 查看已选数量与跳过规则
→ 统一参数与费用预检
→ 创建批次和子任务
→ 持续显示聚合进度
→ 成功/失败/跳过分别落账
→ 仅重试失败项
```

关键规则：

- 默认跳过已有可用结果，除非显式选择重做；
- 切换筛选不能悄悄丢失已选对象；
- 批量“全选”必须说明是当前页、当前筛选结果还是全部数据；
- 子任务独立，批次允许 Partial Success；
- 取消批次不代表 Provider 一定已取消，未知状态需要后台对账。

## 10. Async Task

### 10.1 适用任务

剧本生成/解析、资产提取、生图、生视频、音色生成、故事板/站位图、视频增强、重绘和成片合成均属于异步任务。

### 10.2 最小任务状态

```text
validating → quoted → queued → running
                         ├─ succeeded
                         ├─ failed
                         ├─ cancelled
                         └─ unknown
```

任务需要保存：目标对象、输入快照、引用清单、模型和规格、估算/实际费用、Provider 任务 ID、状态时间戳、错误阶段和结果产物。

### 10.3 反馈层级

1. 对象内联：卡片/镜头上显示当前状态；
2. 批次层：总体进度、成功/失败/跳过；
3. 历史层：任务输入、费用、错误、重试；
4. 全局层：跨页面消息或任务中心。

Toast 不能承担长任务状态。前端超时应进入 `unknown/reconciling`，而不是擅自宣布失败。

## 11. Notification

通知应按时效和严重性分类：

| 类型 | 适用 | 示例 |
|---|---|---|
| Inline status | 与当前对象持续相关 | “场景图生成中”“引用已过期” |
| Toast | 已完成的短动作 | “草稿已保存”“已设为主候选” |
| Banner | 阶段级阻塞/风险 | “剧本有未确认修改，批量生成已禁用” |
| Badge | 聚合计数 | 失败任务数、未完成镜头数 |
| Message center | 跨页面结果 | 长任务完成、账户/系统通知 |
| Dialog | 立即决策 | 删除、覆盖、重新确认、发布 |

成功通知必须说明结果落点；错误通知必须提供恢复动作；费用和合规不能只放在可消失 Toast 中。

## 12. 模式组合规则

```text
列表/卡片：扫描与比较
  └─ Selection：确定当前对象
      └─ Drawer/Inspector：编辑复杂细节
          └─ Modal：完成一次选择或批处理
              └─ Async Task：执行生成
                  └─ Inline + History + Notification：反馈和恢复
```

这套组合有效，是因为每个模式只承担一种认知职责。若把所有字段、历史、模型和任务都塞回卡片，就会破坏扫描效率；若所有编辑都跳新页面，又会丢失上下文。

## 13. 不应照搬的交互

- 不让失效引用只显示弱提示后继续付费生成；
- 不让“点击画风卡”无影响预览地覆盖全局设置；
- 不用 URL 与可见阶段不一致的静默回退；
- 不让无文本名称的图标按钮承担关键操作；
- 不把标准模式和自由画布做成两套保存逻辑；
- 不把高成本批量动作做成一次点击、无范围和价格预检；
- 不让账户经营抽屉长期覆盖生产 Inspector。
