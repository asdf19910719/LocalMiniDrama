# RunningHub RHSTORY 信息架构

> 本文描述“信息如何被分组、定位和跨页面传递”。功能含义见 [product-model.md](./product-model.md)，具体流程见 [user-flows.md](./user-flows.md)。

## 1. 架构原则

RHSTORY 的信息架构由五个相互独立但连续的层次组成：

1. **入口层**：根据用户现有素材决定从哪里开始；
2. **项目层**：管理多集、共享设定和全项目产物；
3. **单集生产层**：按剧本、设定、分镜、短片推进；
4. **资源与工具层**：跨项目复用资产或脱离主线快速试验；
5. **经营与治理层**：管理费用、账户、团队与合规。

这五层不能合并成一张长页面，因为它们的时间尺度和对象粒度不同：项目以周/月存在，单集以生产阶段推进，镜头以秒为单位，任务则以一次异步调用为边界。

## 3. 导航架构

| 导航层 | 常驻内容 | 作用域 | 设计价值 |
|---|---|---|---|
| 全局主导航 | 开始创作、视频重绘、工具箱、我的项目、资产库 | 整个平台 | 让用户按工作目标切域，而不是按技术模型找功能 |
| 项目返回与标题 | 返回、项目名 | 当前项目 | 深层工作台始终保留稳定退出路径 |
| 单集选择器 | 当前集及其他集 | 当前项目 | 支持多集并行生产，避免丢失项目上下文 |
| 阶段步骤条 | 剧本、设定、分镜、短片 | 当前单集 | 同时承担定位、进度、门禁和回访 |
| 阶段工具栏 | 场次筛选、统计、批量、模式、阶段设置 | 当前阶段 | 集中阶段级动作，避免与对象级动作混杂 |
| 对象局部导航 | 角色/场景/道具，故事板/分镜图，历史等 | 当前对象 | 让细节切换不触发页面跳转 |
| 覆盖层 | Modal、Drawer、Inspector | 当前选择 | 保留背景上下文，完成高密度细节操作 |

### 3.1 阶段步骤条的双重语义

步骤条既是导航，也是状态摘要：

- 当前阶段：高对比选中；
- 已完成阶段：可回访；
- 可浏览但未完成阶段：可进入，执行受限；
- 未解锁阶段：禁用；
- 推进动作：“进入下一步”或确认操作改变业务状态，而非单纯换页。

这种设计支持非线性检查，同时保持线性生产约束。问题在于：如果门禁把页面回退到剧本，URL 也必须同步，并显示具体阻塞条件。

## 4. 页面架构

### 4.1 开始创作页

```text
全局 Header
└─ 三入口任务卡
   ├─ 当前拥有的输入
   ├─ 支持格式/限制
   ├─ 预期输出
   └─ 主动作
```

先问“你有什么”，比先问“你要调用哪个模型”更接近用户心智。

### 4.2 项目列表与详情

项目列表负责搜索、排序和继续工作；项目详情负责管理剧集、项目资料和产物。两者分开，使“选择项目”和“编辑项目结构”不会竞争同一页面空间。

项目卡的核心摘要应是名称、封面、集数、更新时间、当前进度和异常，而不是把删除/重命名等低频动作暴露为主按钮。

### 4.3 剧本页

```text
Studio Header：项目 / 集 / 阶段 / 账户
├─ 左栏：分场大纲、数量、字数
├─ 中区：剧本正文编辑器
└─ 底部：保存草稿 / 确认剧本
```

左栏用稳定场次结构导航长文本；中区专注内容；底部把“保存”和“建立下游基线”分离。

### 4.4 设定页

```text
阶段工具栏
├─ 场次筛选
├─ 资产类型标签 + 数量
├─ 标准 / 自由模式
└─ 重新提取 / 批量生成 / 全局画风 / 画布编辑

标准模式：资产卡网格 + 添加卡 + 进入下一步
自由模式：资产目录 + 节点画布 + 小地图/缩放
详情层：资产 Drawer / 画风 Modal / 音色 Modal / 批量生成 Modal
```

资产卡网格支持横向比较，详情抽屉支持纵向深入；两者分工后，卡片无需同时承载提示词、模型、参考图和历史。

### 4.5 分镜页

```text
阶段工具栏：场次 / 镜头数 / 预计时长 / 导入 / 批量
├─ 左栏 Inspector：时长、角色、场景、道具、声音、参考素材、预演
├─ 中栏 Editor：分时码、@引用、模型、规格、价格、生成
├─ 右栏 Result：预览、候选、历史、后处理
└─ 底部 Shot Rail：顺序、选择、插入、删除、合并、状态
```

这是系统最关键的页面架构，因为它将“输入—意图—结果—序列位置”同时呈现。用户可以回答：为什么这个镜头会这样生成、结果放在哪里、前后镜头是什么。

### 4.6 短片页

```text
阶段工具栏：当前镜头 / 总镜头 / 完成数 / 连续播放 / 保存至成片
├─ 主播放器：选中镜头与视频增强
└─ 全集时间线：时标、场次、镜头段、完成/缺失
```

短片页主动减少编辑器和技术参数，把认知任务从“生成”切换成“审核连续性和完成度”。

## 5. 信息对象的页面归属

| 信息 | 主页面 | 次级入口 | 归属原则 |
|---|---|---|---|
| 项目名称、封面、简介 | 项目详情 | Studio Header 摘要 | 详情可编辑，工作台只提供上下文 |
| 单集阶段 | 项目详情 + Studio Header | 项目卡摘要 | 每集独立，不用项目级单一进度代替 |
| 剧本正文与场次 | 剧本页 | 分镜只引用 | 单一文本真相，后续只消费版本 |
| 角色/场景/道具 | 设定页 | 分镜 Inspector、资产库 | 项目资产与单集使用关系分开 |
| 画风 | 设定页全局画风 | 资产局部设置、项目摘要 | 继承关系必须可见 |
| 镜头结构与引用 | 分镜页 | 短片只读摘要 | 生成输入在分镜阶段确定 |
| 逐镜视频候选 | 分镜/短片 | 项目“分镜视频” | 候选和采用结果不能与成片混同 |
| 成片 | 项目“成片” | 短片导出结果 | 合成后形成新产物 |
| 生成任务与费用 | 对象内联 + 历史/消耗看板 | 全局任务入口 | 局部反馈与全局追溯并存 |

## 6. 筛选与选择层级

为避免混淆，筛选和选择必须区分：

- 场次筛选只改变可见范围，不改变资产绑定；
- 资产类型标签只改变列表内容；
- 单对象选择打开 Inspector/Drawer；
- 镜头选择改变分镜工作台的当前上下文；
- 多选只服务批量生成、下载等显式批处理；
- “选用候选”改变当前主结果，是业务状态变更；
- “确认/进入下一步”改变阶段基线或门禁状态。

## 7. 信息架构风险

1. “场次”和“场景资产”中文相近，必须在数据和 UI 中使用不同术语。
2. 标准模式与自由模式若各自保存，将出现双真相；它们只能是同一领域模型的两种投影。
3. `@角色名` 便于阅读，但底层必须绑定稳定实体/版本 ID，防止重命名或排序破坏引用。
4. 工具箱结果若没有“下载、入库、绑定项目/镜头”的明确出口，会成为孤立历史。
5. 项目详情、资产库和设定页都能看到资产时，必须明确是引用、复制还是项目私有版本。

## 8. LocalMiniDrama 可采纳的导航骨架

建议学习：稳定的 Studio Shell、单集阶段轨道、阶段工具栏、分镜四区布局、短片审核页、详情抽屉与全局任务追溯。

不建议复制：强制云账户/钱包、把平台社区作为主流程终点、将调查时点的模型与价格写死、用单一“下一步”掩盖 revision 和失效语义。
