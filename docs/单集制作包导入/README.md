# 外部 AI 单集制作协作

这套流程的目标不是让外部 AI 重新描述整个项目，而是让它在已经讨论确认的剧情基础上，返回“本集内容 + 本集新增资产”。项目自身负责在生成任务时冻结当前资产清单、分配任务 ID，并在导入时恢复完整资产数据。

## 推荐流程

### 持续使用同一个 AI 会话

1. 在外部 AI 会话中讨论并确认第 N 集剧情。
2. 在项目详情页的“分集列表”点击“外部 AI 协作”。
3. 选择“创建下一集”或一个空白集，直接点击“生成本集 AI 制作任务”。
4. 下载 ZIP 并发给外部 AI，让它严格按 `任务说明.md` 返回一个纯 JSON 文件。
5. 点击“导入 AI 返回 JSON”，预览校验后导入。
6. 继续在原会话讨论下一集，重复第 2—5 步。

同一会话通常已经保留前情，不需要每集重复发送“新会话剧情上下文”。任务 ZIP 仍必须每集重新生成，因为它绑定本集目标和生成当时的项目资产快照。

### 新开一个 AI 会话

1. 在“外部 AI 协作”中选择目标集，点击“生成上下文”。
2. 复制或下载上下文，作为新会话的第一份项目背景发给外部 AI。
3. 在该会话中讨论并确认本集剧情。
4. 回到项目生成本集任务 ZIP，交给 AI 输出 JSON，再导入项目。

上下文用于帮助 AI 记住前情和已有设定；真正的导入安全性由任务 ZIP 内的资产清单、严格 Schema 和任务绑定校验保证。

## 任务 ZIP 的三个文件

| 文件 | 用途 |
| --- | --- |
| `任务说明.md` | 指定本集、唯一 `package_id` 和生成规则。AI 应优先服从它。 |
| `当前项目资产.json` | 可引用的现有人物、人物状态、场景和道具。现有资产只能通过 `source_key` 引用。 |
| `返回格式.schema.json` | 当前程序实际使用的严格 JSON Schema。未知字段、缺失必填字段或错误类型会阻止导入。 |

ZIP 不包含完整历史剧本，也不要求外部 AI 重复输出已有资产。新会话所需的前情由单独的 Markdown 上下文提供，避免每集任务包越来越大。

## 返回 JSON 的数据边界

顶层固定为：

- `schema`: 固定为 `local-mini-drama.external-ai-result`。
- `version`: 固定为 `2`。
- `prompt_contract`: 固定为 `base_prompt`，表示外部 JSON 只提交内容层基础提示词。
- `package_id`: 必须原样复制任务说明中的值，用于绑定目标项目、目标集和资产快照。
- `generator`: 可选，记录外部工具、模型和生成时间。
- `audio_plan`: 可选，本集统一音频策略。
- `episode`: 必填，本集标题、梗概、完整剧本和目标时长。
- `new_assets`: 必填，只声明本集首次出现的资产，以及既有人物在本集新增的状态。
- `storyboards`: 必填，按 1 开始连续编号的完整分镜。

### 已有资产

已有资产来自 `当前项目资产.json`，只在分镜引用：

- `scene_ref` 引用已有场景 `source_key`。
- `character_refs[].character_ref` 引用已有人物 `source_key`。
- `character_refs[].variant_ref` 引用该人物已有状态 `source_key`。
- `prop_refs[]` 引用已有道具 `source_key`。

外部 AI 不需要、也不允许重新输出已有角色的性格、外貌或提示词。导入器会依据任务快照从项目数据库恢复这些字段，因此不会再因 AI 省略而把已有设定覆盖为空。`当前项目资产.json` 只公开只读的 `style_id`、中英文名称和中文说明，不公开或接受可覆盖项目风格的提示词。

### 新资产

本集新增的资产使用仅在当前返回 JSON 内有效的 `local_ref`。`local_ref` 在整份文件中必须唯一，且必须以英文字母开头。

- `new_assets.characters`: 新人物。角色功能、性格、外貌、`base_image_prompt`、负向提示词、声音设定和至少一个默认状态均必填。
- `new_assets.character_variants`: 已有人物在本集新增的造型/状态；`character_ref` 必须指向任务清单中的已有人物。
- `new_assets.scenes`: 新场景，状态、语义说明、氛围和 `base_image_prompt` 均必填。
- `new_assets.props`: 新道具，类型、说明和 `base_image_prompt` 均必填。

每个分镜必须分别提供 `base_image_prompt` 与 `base_video_prompt`。它们不是发给模型的最终提示词：系统会在用户真正创建图片或视频任务时，按项目 `style_id` 解析 StyleSpec，加入风格、构图/动作、参考图槽位、对白与音频约束、负向约束，并在调用供应商之前冻结编译结果。

外部 JSON 禁止包含 `style`、`style_id`、`style_prompt_*` 等风格覆盖字段，也禁止包含 `image_prompt`、`video_prompt`、`final_prompt`、`compiled_prompt` 等最终提示词字段。这样即使 JSON 来自其他 AI，也不能绕过项目的风格权威和任务快照。

分镜可以引用同一结果中的 `local_ref`。导入后项目会为这些本地引用生成稳定的 `source_key`。

## 导入时会检查什么

### 导入目标限制

制作包只允许创建新剧集或填充空白剧集，不支持合并、覆盖或追加到已有内容的非空剧集。目标集只要已有剧本/梗概、分镜、分镜媒体或成功导入记录，就会返回 `TARGET_NOT_BLANK`；可改选空白集或创建新剧集，不能强制覆盖。

“导入”只创建或复用结构化资产记录、剧集内容、分镜和引用关系，不等于生成媒体。导入不会自动生成角色图、场景图、分镜图、视频或音频，也不会调用 Provider 或产生生成费用。

- JSON 语法、v2 `base_prompt` 契约、严格字段类型、未知字段和所有必填字段。
- `package_id` 是否存在、是否属于当前项目、是否已经导入过、目标集是否一致。
- 任务创建后项目资产是否变化；变化会提示重新确认，但不会无声使用另一份资产上下文。
- 所有资产引用是否属于任务快照或本次新增资产，新状态是否挂在正确人物下。
- 分镜编号是否从 1 连续递增。
- 空白目标集是否仍可填充。

预览是只读操作；导入也不会创建任何图片/视频生成任务或调用供应商。只有最后确认导入才会在同一事务中创建资产、剧集内容、分镜和来源记录；最终提示词会在之后明确创建生成任务时才编译并冻结。

## 来源追溯

导入成功后，项目详情页和单集制作页都可打开“查看来源 JSON”，其中包含：

- 用户选择的原始文件名和原始 JSON 文本；
- 实际落库前转换出的完整制作包快照；
- 导入报告、资产匹配决策和生成器信息；
- 任务包 ID、任务生成时间和任务资产摘要。

浏览器安全模型不会暴露用户电脑上的完整原始文件路径，因此系统只能可靠保存文件名和文件内容，不能伪造或承诺保存绝对路径。

## 本目录文件

- `制作包schema.json`: 与当前代码导出的外部 AI 增量结果 Schema 一致。
- `制作包示例.json`: 字段完整的结构示例；实际使用时必须把其中的 `package_id` 换成项目刚生成的任务 ID，并使用该任务资产清单中的引用。
- `上游AI生成提示词模板.md`: 手动向外部 AI 说明任务时的补充模板。正常情况下直接使用 ZIP 内自动生成的 `任务说明.md` 即可。
