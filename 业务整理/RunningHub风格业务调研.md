# RunningHub 风格业务调研

## 1. 调研对象与结论

调研页面：

<https://story.runninghub.cn/ai-comic/projects/2090093677004185602/episodes/2090093677008379905/studio?step=art>

结论分为三层：

1. **可以获得当前公开前端构建中内置风格的结构化提示词及主要客户端处理逻辑。** 本次从页面公开加载的前端资源中验证到 140 条风格对象，以及角色、场景、道具的提示词编译逻辑。
2. **可以通过登录页面实际使用的客户端调用，获得线上 169 个系统风格的真实列表提示词和模型映射字段。** 线上每条都有中文 `prompt`，141 条有 `promptEn`，140 条有 `styleKeywords`，140 条绑定了 `t2iModelKey`；当前项目选中“电影超写实”。
3. **仍不能获得服务端生成工作流内部的最终处理。** 前端可证明它保存 `stylePresetId`、选择提示词语言、携带模型键并把风格交给后续资产生成，但服务端是否再次扩写、绑定 LoRA/参考图、修改采样参数或拼接隐藏提示词仍不可见。

本调研适合用来参考产品分层和提示词编译思路，不应把公开构建中的数量、文案或字段当作长期稳定的官方接口契约。

## 2. 已验证的风格数据

公开构建内的 140 条风格按分类统计如下：

| 分类 | 数量 |
| --- | ---: |
| 2D | 77 |
| 3D | 29 |
| 真人 | 34 |
| 合计 | 140 |

登录态实时列表与公开快照并不相同：实时列表为 169 条，比公开快照多 29 条。“电影超写实”可以在实时页面选中，但其名称不在这份 140 条公开快照中。这说明页面会以鉴权接口返回的数据为准，公开构建中的内置对象更接近提示词编译的结构化规则库，而不是完整的线上风格数据库。

公开构建中的结构化对象不是单一提示词字符串，而是结构化风格规格：

| 字段 | 含义 |
| --- | --- |
| `id` | 稳定风格标识 |
| `name` | 风格名称 |
| `category` | 2D、3D 或真人 |
| `description` | 短描述 |
| `basePrompt` | 风格主体描述 |
| `colorKeywords` | 色彩关键词 |
| `lightingKeywords` | 光影关键词 |
| `materialKeywords` | 材质关键词 |
| `cameraKeywords` | 镜头与构图关键词 |
| `environmentKeywords` | 环境关键词 |
| `qualityKeywords` | 质量关键词 |
| `negativeKeywords` | 负面提示词 |
| `suitableAssetTypes` | 适用的资产类型 |

这说明 RunningHub 的核心做法不是“选择名称后把名称拼进提示词”，而是先把风格当作一份可计算的规格，再针对不同资产生成专用提示词。

### 2.1 登录接口的真实字段

页面实际调用 `POST /aivideo/styles/list`。使用页面自身的已登录客户端读取后，返回 4 个分组：

| 分组键 | 名称 | 数量 |
| --- | --- | ---: |
| `realistic` | 真人 | 39 |
| `3d-special` | 3D | 39 |
| `2d` | 2D | 91 |
| `custom` | 我的风格 | 0 |

线上预设的实际字段包括：

| 字段 | 作用 |
| --- | --- |
| `id` / `key` | 数字 ID 与稳定业务键 |
| `label` / `labelEn` | 中英文名称 |
| `prompt` / `promptEn` | 中英文风格提示词；中文提示词 169/169，英文提示词 141/169 |
| `styleKeywords` | 结构化风格关键词；140/169 有值 |
| `coverUrl` | 风格封面 |
| `source` | `SYSTEM` 或用户风格来源 |
| `t2iModelKey` / `i2iModelKey` | 文生图、图生图模型映射 |

169 个系统风格中有 140 个绑定了 `t2iModelKey`，分布于 Seedream、Nano、悠船/Niji 等不同图片模型；29 个未绑定专用文生图模型。当前 169 个风格的 `i2iModelKey` 均为空。

### 2.3 真人影视风格示例

公开快照中包含“复古电影摄影风格”“悬疑电影风格”“90年代港片风格”“韩国冷淡电影风格”“蓝橙色调影视风格”“国产都市写实”“赛博朋克电影风格”等真人类预设。

以“复古电影摄影风格”为例，其主体描述强调胶片颗粒、年代色偏、钨丝灯、街头烟火气、轻微褪色和抓拍感；同时独立提供 35mm 电影镜头、纪录片式构图、真实皮肤、年代服装和负面质量词。这比 LocalMiniDrama 当前“电影感”的一段中英文长提示词粒度更细。

以“悬疑电影风格”为例，其主体描述强调低照度、高反差、负空间和压迫阴影；色彩、光影、镜头及环境又分别约束冷灰黑白、低调光、倾斜/近景压迫构图、走廊与雨夜空间。

## 3. 页面业务流程

### 3.1 项目级选择

页面的风格设置同时包含：

- 官方风格与“我的风格”两个来源。
- 风格卡片选择和画面比例设置。
- 可选的“风格补充”，用于追加光影、色彩、镜头等项目级说明。
- 项目内统一性提示：以所选风格为主视觉，并保持色彩、光影与角色造型一致。

项目/剧集保存的关键字段是 `stylePresetId`。该标识会随剧集更新、剧本确认及资产偏好保存进入后续链路，而不是把完整提示词散落在每次表单提交里。

### 3.2 全局与局部覆盖

页面具备“全局画风”和“局部画风（仅影响该素材）”的概念。单个资产可以：

- `stylePresetId = null`：跟随全局画风。
- 指定另一个 `stylePresetId`：只覆盖当前资产。

对应客户端请求为 `/aivideo/assets/style/update`。这使角色、场景或道具可以在保留项目主风格的同时做局部调整。

### 3.3 自定义风格

用户可以创建、修改和删除私有风格，字段包括风格名称、提示词和封面图。保存前存在内容检查；删除前会检查该风格是否正被使用。

页面提示的业务语义是：已经生成的镜头不受删除影响，但依赖该自定义风格的项目将失去继续按该风格重新生成素材的能力。这个说明把“风格配置”和“历史生成结果”区分开，避免用户误以为改风格会追溯修改成品。

### 3.4 图片提取风格

客户端还暴露了 `/aivideo/upload/extract-style`，说明自定义风格不只支持手填提示词，也预留了从参考图提取风格描述的能力。

## 4. 提示词处理逻辑

### 4.1 风格解析

登录页面的真实选中规则是：

1. 先用项目/剧集的 `stylePresetId` 在实时列表中按 `id` 或 `key` 查找预设。
2. 系统风格在国内站优先使用 `prompt`，为空时回退 `promptEn`，再回退 `description`。
3. 国际站优先使用 `promptEn`，为空时回退 `prompt`，再回退 `description`。
4. 用户自定义风格使用 `prompt`，为空时回退 `description`。
5. 选中结果在前端同时保存 `presetId`、展示名称、解析后的提示词和 `t2iModelKey`。

以下规则属于公开构建中的分资产提示词编译层：

处理入口先标准化风格名称：去首尾空白、移除内部空格，并剥离末尾“风格”二字后匹配预设。匹配不到时会走按名称关键词推断的回退策略，例如：

- 水墨、中国奇幻、武侠等进入东方审美规则。
- 赛博、霓虹进入数字都市与高对比边缘光规则。
- 3D、PBR、UE5 进入三维材质和资产级细节规则。
- 复古、胶片、90 年代进入颗粒、褪色和年代光源规则。
- 真人、电影进入电影写实视觉规则。

如果调用方额外传入风格提示词，它会覆盖该风格对象的 `description` 和 `basePrompt`，但仍保留其余结构化维度供编译使用。

### 4.2 角色提示词编译

角色生成不是简单拼接，客户端会先解析角色信息并构造：

- 原始人物设定、身份、性格、外貌和多套服装。
- 世界观、职业/阶层、脸部气质、服装材质与配色。
- 所选风格的基础描述、色彩、光影、材质、镜头、环境与质量词。
- 场景、道具、传播记忆点和故事适配分析。
- 中文正向提示词、英文正向提示词和负面提示词。

对于“纯背景正面全身角色资产”，还会强制单人、居中、正面、全身、干净背景，并从正向词中清理三视图/转面等表达，同时在负面词中加入多视角、背面、侧面、分镜、多人物和复杂背景等约束。

### 4.3 场景与道具提示词编译

场景和道具共用结构化风格对象，但约束不同：

| 资产 | 专用约束 |
| --- | --- |
| 场景 | 完整环境、空间纵深、材质与气氛；无人；不能是纯背景 |
| 道具 | 单一道具居中、干净中性背景；不能带场景、其他物体或人物 |

两者都生成中英文提示词，并补充低质量、模糊、杂乱、变形、文字、水印、人物/手部等负面约束。

### 4.4 请求注入

最终生成请求会通过公共帮助函数把选中的系统风格标识注入为 `styleId`。风格的作用因而有两条路径：

1. 客户端根据结构化风格生成适合当前资产的正负提示词。
2. 生成请求继续携带稳定 `styleId`，让服务端或工作流选择相应的系统参考风格。

这比只传一段文本更容易做到提示词一致、资产差异化和服务端演进。

## 5. 与 LocalMiniDrama 的对比

| 维度 | LocalMiniDrama 当前 | RunningHub 公开流程 |
| --- | --- | --- |
| 风格标识 | `dramas.style` 短标识 | `stylePresetId` 稳定 ID |
| 风格内容 | 中英文长字符串 | 基础描述 + 7 类关键词 + 适用资产 |
| 保存位置 | 项目 metadata 保存提示词快照 | 项目/剧集保存 ID，资产可单独覆盖 |
| 资产适配 | 各服务自行注入或拼接 | 统一编译器按角色、场景、道具输出 |
| 负面提示词 | 分散在各生成服务 | 风格级负面词与资产级负面词合并 |
| 自定义风格 | 一个项目内的自由文本 | 可复用私有风格实体，支持 CRUD 和封面 |
| 局部覆盖 | 没有统一模型 | 全局跟随或单资产 `stylePresetId` 覆盖 |
| 历史素材 | 切换后不自动重做，但提示较弱 | 明确说明旧生成结果不受影响 |
| 模型/工作流 | 主要依赖文本条件 | 文本条件 + 请求中的 `styleId` |

## 6. 建议参考的目标业务模型

建议参考 RunningHub 的分层方式，但不要直接复制其文案或接口：

```text
StylePreset（可复用风格实体）
  ├─ 基础：id、名称、分类、封面、版本
  ├─ 视觉：基础描述、色彩、光影、材质、镜头、环境、质量词
  ├─ 约束：负面词、适用资产类型
  └─ 文本：中文规格、英文规格
          ↓
ProjectStyleBinding（项目/剧集全局选择 + 补充说明 + 快照）
          ↓
AssetStyleOverride（角色/场景/道具：跟随全局或局部覆盖）
          ↓
StylePromptCompiler（按资产类型编译正向词、负向词和模型参数）
          ↓
图片 / 视频生成请求（携带 stylePresetId、styleSnapshot、prompt）
```

推荐按以下优先级落地：

1. **先统一数据源。** 将前后端重复预设收敛为服务端风格实体或共享配置，前端只读取展示数据。
2. **增加结构化字段。** 从现有 `prompt/promptEn` 平滑迁移到色彩、光影、材质、镜头、环境、质量与负面词；保留旧长提示词兼容。
3. **建立项目绑定快照。** 保存 `stylePresetId + presetVersion + styleSnapshot + extraPrompt`，确保预设日后修改时旧项目仍可复现。
4. **建立统一编译器。** 按角色、场景、道具、分镜、图片和视频分别编译，业务服务不再各自手写风格拼接。
5. **增加局部覆盖。** 资产级字段允许 `null` 跟随全局，或指定其他预设；界面明确显示当前来源。
6. **补齐变更语义。** 切换/删除风格时提示“不改变历史结果；重新生成时使用新风格”，并标记旧素材为“基于旧风格生成”。
7. **最后再接模型能力。** 如果具体生成提供方支持 LoRA、参考风格或工作流 ID，再由适配层把内部 `stylePresetId` 映射到模型参数；不支持时仍使用编译后的文本提示词。

## 7. 不建议直接照搬的部分

- 公开快照中部分预设字段较通用，个别描述存在模板化重复，不能因为“结构化”就认为每个词都经过独立验证。
- 前端构建哈希和内置数据可能随发布变化，不适合作为运行时数据源。
- 登录接口能返回提示词、风格关键词和模型键，但服务端是否二次改写提示词、绑定 LoRA、参考图或工作流节点仍无法由前端证明。
- LocalMiniDrama 同时支持不同图片和视频提供方，结构化风格需要经适配层转成各模型能理解的参数，不能把某一家平台的 `styleId` 直接当成通用标准。

## 8. 证据与验证边界

已验证：

- 指定页面可以返回 Nuxt 单页应用壳和公开静态资源。
- 当前公开构建中存在 140 个完整结构化风格对象。
- 登录态指定项目的系统风格列表实时显示 169 条：真人 39、3D 39、2D 91。
- 当前项目的全局风格是“电影超写实”，页面卡片处于选中状态。
- 使用页面自身的已登录客户端成功取得实时 169 条预设；每条均有中文 `prompt`，并确认提示词语言选择、模型键与 `stylePresetId` 查找规则。
- 已获得“电影超写实”的线上真实中文提示词；该预设没有英文提示词、结构化关键词或专用模型键。
- 风格卡片 DOM 本身只包含名称、封面和选中状态；完整字段来自页面调用的鉴权列表接口。
- 客户端存在风格列表、私有风格 CRUD、使用检查、图片风格提取、项目偏好、资产局部覆盖等请求。
- 客户端存在角色、场景与道具的分类型提示词编译和 `styleId` 请求注入。

未验证：

- 用户“我的风格”内容。
- 服务端私有实现、模型节点、LoRA/参考图绑定和最终服务端提示词。
- 公开快照中的 140 条是否全部与服务端当前版本逐字段一致。

风格实时列表来自鉴权接口 `POST /aivideo/styles/list`。未登录调用返回：
