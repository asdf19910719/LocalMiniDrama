# 当前项目风格业务说明

## 1. 业务结论

LocalMiniDrama 的画面风格是项目级生成协议，不是后期滤镜，也不是前端临时拼接的一段文字。项目只保存一个稳定 `style_id`；后端在每次创建图片或视频任务时解析对应 StyleSpec、编译最终提示词、执行模型能力校验并冻结快照，然后才允许调用供应商。

```text
选择项目风格 style_id
  ↓
后端 StyleRegistry 解析带版本 StyleSpec
  ↓
图片/视频 Compiler 合并内容、模式、引用、对白、音频与负向约束
  ↓
模型能力预检
  ↓
持久化不可变生成快照
  ↓
提交图片/视频供应商
```

项目之后切换风格只影响新任务，历史任务的最终提示词、引用和风格版本保持不变。已有图片或视频不会自动重做。

## 2. 风格目录与字段

系统目录由后端 `backend-node/src/catalog/stylePresets.v1.json` 唯一拥有，共 169 个风格。前端不再维护第二份提示词表，而是通过 `/api/v1/styles` 读取。

每个 StyleSpec 的核心字段如下：

| 字段 | 业务用途 |
| --- | --- |
| `id` | 稳定风格 ID，例如电影超写实为 `rh-101-cinematic` |
| `version` | 风格版本；写入生成快照，保证可复现 |
| `labelZh` / `labelEn` | 中英文展示名称 |
| `descriptionZh` | 默认展示给用户的具体风格说明 |
| `promptZh` / `promptEn` | 可直接参与模型请求的真实风格约束 |
| `keywords` | 色彩、光影、材质、镜头、环境、质量和负向约束 |
| `suitableAssetTypes` | 可用于人物、状态、场景、道具、分镜、视频等范围 |
| `recommendedCapabilities` | 渲染类型、图生图、角色一致性、多参考图、首选提示词语言与 RunningHub 模型键 |
| `preview` | 本地预览路径和回退渐变，不允许运行时热链 |

完整目录可从 [LocalMiniDrama风格目录v1.json](./LocalMiniDrama风格目录v1.json) 查看和二次处理。

## 3. 电影超写实风格

当前“电影感”对应 `rh-101-cinematic`，界面名称为“电影超写实 / Cinematic Hyper-realistic”。

中文原始风格提示词：

> 真人电影写实摄影，原生相机直出，无 AI 塑料感，自然真实皮肤肌理，原生环境光影，柔和自然明暗，丁达尔效应，真实景深虚化，细腻原生材质，轻微自然噪点，真人实拍质感，色彩自然还原

英文模型提示词由目录构建器生成一段完整 art direction，以 `Create a Cinematic Hyper-realistic live-action cinematic look...` 开始，明确要求同一视觉语言贯穿人物面孔、服装、道具、建筑、气氛、色彩、主辅轮廓光、镜头、景深、构图、材质和可运动调度，并附带畸形肢体、身份漂移、水印、低清和风格混合等规避项。逐字全文见目录 JSON，避免在多个文档复制后产生漂移。

中文说明不是只给界面看的“营销文案”：`promptZh` 和 `promptEn` 都是生成约束。语言解析器按模型配置、模型能力和 StyleSpec 推荐顺序选择 `zh`、`en` 或 `mixed`；电影风格不会简单追加成 `Style: cinematic`。

## 4. UI 与交互

项目列表新建项目、项目详情、制作台和自由创作均使用同一个后端画风库：

1. 四列视觉卡片展示本地预览、中文名、英文名和简述。
2. 支持“全部 / 真人 / 3D / 2D / 我的”分类与中英文搜索。
3. 选中态立即展示，详情抽屉可查看适用对象、能力建议以及实际中英文提示词。
4. 自定义风格不是随手输入的一次性字符串，而是保存为 `custom:<uuid>` 的结构化 StyleSpec；编辑会提升版本。
5. 项目设置旁持续显示当前风格摘要，明确提示它会作用于人物、场景、道具、分镜图片和视频。
6. 项目内生成面板不再提供请求级风格覆盖；自由创作不绑定项目时必须显式选择一个目录风格。

## 5. 图片提示词编译

统一图片编译器接收：目标类型、生成模式、基础内容提示词、负向提示词、StyleSpec、语言和参考图注册表。

编译顺序固定为：

1. 风格约束：中文、英文或混合 StyleSpec 提示词。
2. 模式约束：规定资产输出形态。
3. 内容主体：人物外貌、状态变化、场景语义、道具结构或分镜内容。
4. 引用绑定：按稳定顺序生成 `@图片N` / `@ImageN`。
5. 负向约束：业务负向词与风格负向关键词去重合并。

已覆盖的模式：

| 目标 | 模式 |
| --- | --- |
| 基础人物 | `SINGLE`、`TURNAROUND` |
| 人物状态 | `SINGLE`、`TURNAROUND`，可选基础人物身份参考 |
| 场景 | `NORMAL`、`MULTI_VIEW`、`PANORAMA`、`TOP_DOWN` |
| 道具 | `SINGLE` |
| 分镜图片 | `FRAME`，含主图、首帧、尾帧 |

电影风格在图片中位于首段；随后才是“角色转面图”“全景建立镜头”“俯视空间布局”等业务模板和具体内容，因此风格不会被长内容提示词稀释。

## 6. 视频提示词编译

统一视频编译器同样以 StyleSpec 为第一段，并继续组合：

- 参考图与首尾帧绑定；
- 镜头景别、机位、运动与构图；
- 动作起点、过程、终点和按时长组织的时间线；
- 逐字对白、说话人和表演方式；
- 环境声、音效、配乐 cue、静默与转场音频桥；
- 时长、画幅、分辨率等输出约束；
- 负向提示词。

普通视频、Omni 多参考和 H3 最终都先解析同一个项目 StyleSpec。H3 保留其专用草稿和门禁，但风格上下文在进入专用序列化之前已经统一；不再使用普通路径的 `. Style: ...` 末尾追加方式。

## 7. 模型映射与能力校验

StyleSpec 中的模型键和能力字段属于“推荐与校验”，不会偷偷切换供应商或产生付费调用。系统会检查参考图上下限、真人参考是否允许、图片/视频能力和推荐渲染类型：

- 有阻断错误：不保存为可提交状态，不调用供应商。
- 只有建议偏差：保存 warning 并允许用户继续使用当前模型。
- 校验通过：保存 `ok`，再进入提交阶段。

RunningHub 原始导出中多数 `t2iModelKey` / `i2iModelKey` 为 `null`；项目如实保留 `null`，不会臆造映射。完整原始字段见 [RunningHub真实风格提示词与模型映射.json](./RunningHub真实风格提示词与模型映射.json)。

## 8. 外部 JSON 的边界

外部 AI 单集结果只支持：

```json
{
  "schema": "local-mini-drama.external-ai-result",
  "version": "2",
  "prompt_contract": "base_prompt"
}
```

新增资产填写 `base_image_prompt`，分镜分别填写 `base_image_prompt` 和 `base_video_prompt`。外部结果禁止提交 `style`、`style_id`、`style_prompt_*`，也禁止提交 `image_prompt`、`video_prompt`、`final_prompt`、`compiled_prompt`。导入器把基础提示词投影到项目业务字段，但预览和导入阶段绝不创建生成任务或调用供应商；只有用户之后明确创建任务时，系统才以项目 StyleSpec 编译最终提示词。

## 9. 快照与审计

供应商调用前冻结：

- `style_id` 与 `style_version`；
- 选定语言；
- 最终正向和负向提示词；
- 引用图顺序、角色/场景/道具语义；
- 编译分段；
- 模型能力校验结果；
- 视频模型、工作流、尺寸、帧率、种子、时长和音频设置。

图片任务抽屉可以查看本次实际提示词、负向词、StyleSpec 版本、引用数量和冻结状态；视频历史保留最终 prompt 与完整配置快照。这个设计用于回答“这张图/这个视频当时究竟使用了什么”，而不是根据当前项目设置反推。

## 10. RunningHub 预览证据边界

本项目运行时有 169 个本地预览文件。当前真实来源状态是：

- 12 张：从已登录 RunningHub 画风库实机截图中裁取，清单状态 `runninghub-screenshot`。
- 157 张：因浏览器标签被另一个自动化会话占用、无法读取登录态接口响应而生成的本地回退图，清单状态 `fallback`。

所有状态都记录在 `backend-node/src/catalog/stylePreviewManifest.v1.json`，包含本地路径、尺寸、SHA-256 和采集时间。运行时不热链外站；回退图不会被标注为 RunningHub 原始预览。未来只需提供带 `runningHubId → sourceUrl` 的受控映射并重跑抓取脚本，即可原位替换，不改变 StyleSpec ID 或项目数据。
